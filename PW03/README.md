## Призначення

Застосунок прогнозує споживання електроенергії, зберігає
персональні прилади та історію прогнозів, отримує енергетичні
сценарії через навчальний REST API.

PW03 створено як окремий проєкт на основі PW02.
Application ID: `ua.kpi.energyforecast.pw03`.

## Реалізовані функції

- Додавання, редагування та видалення приладів із валідацією.
- Розрахунок споживання, графік та історія прогнозів.
- Каталог сценаріїв: пошук, категорії, сортування та деталі.
- Імпорт приладів сценарію в персональний профіль.
- Retrofit і Gson для отримання та перевірки JSON.
- Постійний кеш Room із транзакційним оновленням.
- Перегляд кешу при недоступному сервері за чинної сесії.
- Серверний вхід, збереження токена в DataStore та вихід.
- Контроль строку дії сесії, ролі USER і ADMIN.
- Серверна перевірка прав на адміністративний ресурс.
- Централізовані повідомлення про мережеві помилки та Snackbar.
- До трьох спроб GET при визначених тимчасових збоях.
- Внутрішній журнал без паролів, токенів і тіл запитів.

## Структура

- `app/` — Android-застосунок, тести та схеми Room.
- `server/` — локальний FastAPI, навчальні дані та серверні тести.
- `docs/requirements.md` — вимоги.
- `docs/api-contract.md` — контракт API та політика повторів.
- `docs/verification.md` — результати й межі перевірок.

## Запуск

1. В Android Studio відкрити теку `PW03` та виконати Gradle Sync.
2. Підготувати й запустити сервер за інструкцією
   [server/README.md](server/README.md).
3. Запустити застосунок на стандартному Android Emulator.

Адреса API для емулятора: `http://10.0.2.2:5156/`.
HTTP для локального сервера дозволено в debug-конфігурації.

Навчальні акаунти:
- `demo@energy.test` / `Demo1234` — USER.
- `admin@energy.test` / `Admin1234` — ADMIN.

Для фізичного пристрою потрібне окреме налаштування адреси API
та доступу до сервера.

## Межі навчальної реалізації

Сервер використовує вигадані облікові записи й каталог із JSON.
Реєстрація не реалізована. Персональні прилади та історія
зберігаються локально й на сервер не передаються.

Клієнт читає JWT для стану UI та контролю строку дії.
Криптографічну перевірку токена й прав виконує сервер.

Екран деталей сценарію використовує кешований каталог.
Окремий endpoint деталей реалізований і перевіряється тестами.
