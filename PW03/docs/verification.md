## 2. Статуси

- НЕ ПЕРЕВІРЕНО — перевірка ще не виконана.
- ПРОЙДЕНО — результат відповідає очікуваному.
- НЕ ПРОЙДЕНО — зафіксовано відхилення.
- ЗАБЛОКОВАНО — перевірка неможлива через конкретну перешкоду.

Успішну перевірку фіксуємо лише після фактичного виконання.
Для фінальної перевірки записуємо commit SHA.

## 4. Заплановані автоматичні перевірки

### Локальні Android-тести

- JSON DTO та перетворення в моделі.

- Вибір кешу й віддаленого джерела.

- Заголовок Authorization.
- Обмеження повторів та успіх після тимчасового збою.
- Відсутність повторів для 401, 403, 404 і невалідного JSON.
- Поширення скасування корутин.
- Переходи станів ViewModel.
- Вихід і завершення строку дії сесії.

### Інструментальні Android-тести

- Запис і читання кешу через Room.
- Міграція бази зі збереженням наявних даних.
- Відсутність часткового запису при помилці.
- Відновлення й очищення токена в DataStore.
- Відображення UI відповідно до ролі.

Перед запуском перевірити очікуваний application ID
у скопійованому ExampleInstrumentedTest.

### Серверні тести

- Правильний і неправильний вхід.
- Запит без токена.
- Пошкоджений та прострочений токен.
- USER отримує 403 для адміністративного ресурсу.
- ADMIN отримує адміністративний підсумок.
- Невідомий сценарій повертає 404.
- Структура успішних відповідей і помилок.
