# EnergyForecast — навчальний API

## Адреси

Сервер на комп’ютері:
http://127.0.0.1:5156/

Стандартний Android Emulator:
http://10.0.2.2:5156/

Документація:
http://127.0.0.1:5156/docs

Сервер локальний. HTTP дозволяється в Android лише
для локальних адрес у debug-конфігурації.

## Авторизація

POST /auth/login відкритий.
Решта endpoint потребують заголовка:

Authorization: Bearer <token>

Навчальні акаунти:
- demo@energy.test / Demo1234 — USER.
- admin@energy.test / Admin1234 — ADMIN.

JWT підписується HS256.
Payload містить sub, email, name, role, iat, exp.
Час — Unix time у секундах.
Звичайний строк дії — 3600 секунд.

Ключ підпису залишається на сервері.
Зміна ключа робить старі токени недійсними.

## POST /auth/login

Запит:

{
"email": "demo@energy.test",
"password": "Demo1234"
}

Відповідь HTTP 200:

{
"accessToken": "<signed-jwt>",
"tokenType": "Bearer",
"expiresAt": 1900000000
}

expiresAt відповідає exp у токені.
Число наведено лише як приклад формату.

Email обрізається по краях і переводиться в нижній регістр.
Пароль порівнюється без зміни регістру та без обрізання.

## GET /scenarios

Доступ: USER, ADMIN.

Відповідь HTTP 200:

{
"scenarios": [
{
"id": "home-office",
"name": "Домашній офіс",
"category": "OFFICE",
"description": "Навчальний приклад робочого місця",
"devices": [
{
"id": "laptop",
"name": "Ноутбук",
"powerWatts": 60.0,
"hoursPerDay": 8.0,
"deviceCount": 1
}
]
}
]
}

Категорії: HOME, OFFICE, MIXED.
Список містить повні сценарії з вкладеними приладами.
Порожній каталог повертається як {"scenarios": []}.

## GET /scenarios/{id}

Доступ: USER, ADMIN.

HTTP 200: один об’єкт сценарію тієї самої структури,
що й елемент scenarios.
Невідомий ID: HTTP 404, SCENARIO_NOT_FOUND.

## GET /admin/summary

Доступ: лише ADMIN.

Поточний навчальний каталог повертає:

{
"scenarioCount": 3,
"devicePositionCount": 8
}

devicePositionCount рахує позиції, без множення на deviceCount.
USER отримує HTTP 403.

## Формат помилки

{
"error": {
"code": "FORBIDDEN",
"message": "Потрібні права адміністратора"
}
}

| HTTP | Код |
|---|---|
| 400 | VALIDATION_ERROR |
| 401 | INVALID_CREDENTIALS |
| 401 | TOKEN_REQUIRED |
| 401 | INVALID_TOKEN |
| 401 | TOKEN_EXPIRED |
| 403 | FORBIDDEN |
| 404 | SCENARIO_NOT_FOUND |
| 503 | TEMPORARILY_UNAVAILABLE |

Інші недоступні маршрути або методи повертають HTTP_ERROR.

401 під час входу — помилка облікових даних.
401 захищеного запиту — завершення сесії.
403 — відмова в доступі без завершення сесії.

## Перевірка JSON в Android

Обов’язкові поля й типи перевіряються до запису в Room.
ID та назви не можуть бути порожніми.
ID сценаріїв у списку й приладів усередині сценарію унікальні.
Сценарій містить від 1 до 50 позицій.

Правила приладів:
- назва після trim: 1–60 символів;
- потужність: понад 0 і до 100000 Вт;
- час: 0–24 години;
- кількість: ціле число 1–1000;
- числові значення скінченні.

Невалідний список повністю відхиляється.
Попередній коректний кеш не змінюється.

## Заплановані повтори в Android

Лише GET при SocketTimeoutException, ConnectException,
UnknownHostException, SocketException або HTTP 502, 503, 504.

Відсутність активної мережі, пошкоджений JSON і невалідні
значення відповіді не спричиняють автоматичних повторів.
Не більше трьох спроб загалом.
Затримки перед повторами: 0,5 і 1 секунда.

Не повторюються:
- вхід;
- HTTP 400, 401, 403, 404;
- пошкоджений JSON і невалідні дані;
- скасовані корутини.

## Керовані збої сервера

ENERGY_FAULT:
- none — звичайна відповідь;
- transient503 — перші два запити до шляху повертають 503;
- always503 — постійний 503;
- malformed — пошкоджений JSON;
- invalid — від’ємна потужність;
- timeout — затримка 30 секунд.

Режим задається перед запуском сервера.
Лічильники скидаються при перезапуску.
Авторизація перевіряється перед імітацією збою.
