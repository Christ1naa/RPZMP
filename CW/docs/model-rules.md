# Правила моделі DocTrack

Реалізовано для пункту 4 курсової. `DocumentRecord` містить дані, `RecordValidator` перевіряє їх перед збереженням, а `statusOn(today)` обчислює статус на задану дату. Ці компоненти не залежать від Android.

## Валідація

| Поле | Правило |
| --- | --- |
| Назва | Не порожня і не складається лише з пробілів |
| Дата видачі | Необов’язкова; якщо задана, не пізніше терміну |
| Термін | Обов’язковий `LocalDate`; минулі дати дозволені |
| Сума рахунку | Обов’язковий `Long > 0`, у копійках/центах |
| Валюта рахунку | Обов’язкова: EUR, UAH або USD |
| Сума/валюта документа | Відсутні (`null`) |
| Оплата документа | `false`; стан оплати застосовується лише до рахунку |

Одна дата може бути одночасно датою видачі та терміном. Обмеження «дата видачі не в майбутньому» не вводиться. Усі три підтримувані валюти мають дві десяткові позиції. Перетворення тексту форми на дату та суму буде реалізовано разом із формою; некоректний текст не можна передавати в типізовану модель.

Валідатор повертає список усіх помилок, порожній список означає успіх. Він не змінює поля і не кидає винятки через помилки користувача. Конструктор моделі не запускає перевірку автоматично: майбутній сценарій збереження має явно викликати `RecordValidator.validate(record)` та зберігати лише запис без помилок.

## Статуси

| Умова (перевіряється зверху вниз) | Статус |
| --- | --- |
| Рахунок оплачено | `PAID` — оплачено |
| Термін раніше сьогодні, документ | `EXPIRED` — строк дії минув |
| Термін раніше сьогодні, неоплачений рахунок | `OVERDUE` — оплату прострочено |
| Термін сьогодні | `DUE_TODAY` — термін сьогодні |
| Залишилося 1–7 календарних днів включно | `DUE_SOON` — термін наближається |
| Залишилося понад 7 днів | `ACTIVE` — термін ще не наближається |

Вікно 7 днів — прийняте правило першої версії, не вимога викладача. Термін включає весь останній день. Статус не є полем `DocumentRecord`, тому не застаріває в сховищі. UI має передавати актуальну локальну дату; автоматичне оновлення екрана при зміні дня буде вирішено на етапі UI. Функція статусу призначена для записів, які пройшли валідацію.

## Приклад використання

```kotlin
val errors = RecordValidator.validate(record)
if (errors.isEmpty()) {
    val status = record.statusOn(LocalDate.now())
    // Подальше збереження та відображення додамо разом із формою.
}
```

Перевірки: `RecordValidatorTest` (20 тестів) та `RecordStatusTest` (11 тестів). Покрито відсутні поля, несумісні поля документа, одночасні помилки, мінімальну суму, межі 0/1/7/8 днів, оплачений рахунок із минулим терміном, високосний день та демонстраційні записи.

Повний запуск в Android-проєкті (PowerShell з папки `CW`):

```powershell
.\gradlew.bat :app:testDebugUnitTest --console=plain
```

Форми, блокування збереження та відображення нових статусів на картках до цього кроку не входять.
