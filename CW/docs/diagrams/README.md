## Як читати

- Класи: `?` позначає nullable-тип Kotlin. Стереотип `object` означає Kotlin singleton. `statusOn` показано як залежність із приміткою про функцію-розширення, а не як збережене поле або окремий клас. Діаграма відбирає основні типи предметної моделі; типи форми й групування додатково описані в [таблиці моделей](../data-model.md).
- Компоненти: блоки — логічні модулі й групи файлів. `DocTrackApp` є composable-функцією, що координує стан і переходи, а не реалізованим ViewModel або Repository. Стрілки показують використання й передачу даних/дій, а не потоки мережі.
- Послідовність: учасники відображають ролі composable-функцій і функцій логіки. Перевірка обчислюється при зміні введення; «Зберегти» використовує вже підготовлений результат. Невдале введення не змінює список.
- Навігація: форми створення й редагування використовують той самий `RecordFormScreen` із різними початковими даними. Діалог підтвердження не є маршрутом. Повернення з деталей залежить від місця їх відкриття.

## Відтворення

PlantUML 1.2025.2, UTF-8. Класи, компоненти й навігація використовують Smetana, щоб не вимагати окремого Graphviz:

```powershell
java -jar plantuml.jar -charset UTF-8 -tsvg *.puml
```

Зміна коду, що впливає на моделі, правила або переходи, потребує перегляду відповідного `.puml` та повторного експорту `.svg`.
