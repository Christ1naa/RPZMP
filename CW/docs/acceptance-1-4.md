## Фінальна перевірка саме версії для здачі

1. Зафіксувати гілку й коміт: `git branch --show-current`, `git rev-parse HEAD`. За наявності локальних змін зазначити їх через `git status --short`. Після зміни коду перевірити його повторно.
2. Із папки `CW` виконати:

   ```powershell
   .\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
   ```

3. Підключити один емулятор або пристрій з API ≥26; виконати п’ять Compose UI-тестів:

   ```powershell
   .\gradlew.bat :app:connectedDebugAndroidTest --console=plain
   ```

   `DocTrackUiTest` перевіряє: відмову збереження некоректної форми й виправлення; суму, валюту та оплату рахунку; підтвердження скасування; відновлення чернетки; навігацію й відновлення створеного запису. Емуляція saved instance state у Compose не замінює перевірку реального повороту Activity.

4. Переглянути звіти й записати фактичні числа:

   | Звіт | Шлях від `CW` |
   | --- | --- |
   | JVM | `app/build/reports/tests/testDebugUnitTest/index.html` |
   | Lint | `app/build/reports/lint-results-debug.html` |
   | UI на пристрої | `app/build/reports/androidTests/connected/` |

   Успіх `lintDebug` не означає відсутність попереджень. Для UI записати результати саме з HTML-звіту, а не кількість оголошених тестів.

5. Виконати [ручні сценарії](ui-checks.md), включно з TalkBack, горизонтальним екраном і великим шрифтом. Записати модель пристрою, Android/API та дату. Результат не вважати підтвердженим, доки його не перевірено.
6. Зняти фінальні скриншоти, включно з «Сервером»; вставити їх до звіту. Після зміни компонування списку попередній скриншот головного екрана потрібно оновити.
