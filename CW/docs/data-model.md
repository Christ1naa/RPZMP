# Моделі даних і правила

Базова версія коду: [`61cd8905`](https://github.com/Christ1naa/RPZMP/commit/61cd8905eed8a0faa016a609fbacb6a76b74dc7b), `versionName = 1.0`, `versionCode = 1`.

## DocumentRecord

Документ і рахунок представлені одним незмінним `data class`. Тип запису визначає застосовність фінансових полів. Позначка `?` означає nullable-тип Kotlin.

| Поле | Тип | Значення за замовчуванням / обов’язковість | Призначення й правило |
| --- | --- | --- | --- |
| `id` | `String` | UUID, якщо не передано | Ідентифікатор; при редагуванні незмінний. Навігація та заміна у списку використовують цей ID. Окремої перевірки унікальності у валідаторі немає |
| `title` | `String` | Обов’язкове | Після обрізання пробілів 1–120 символів; форма зберігає обрізаний текст |
| `type` | `RecordType` | Обов’язкове | `DOCUMENT` або `BILL` |
| `deadline` | `LocalDate` | Обов’язкове | Діє до / оплатити до; рік 1–9999, минула дата дозволена |
| `issuer` | `String?` | `null` | Організація; порожнє введення форма перетворює на `null` |
| `issuedOn` | `LocalDate?` | `null` | Дата видачі; рік 1–9999, не пізніше `deadline` |
| `amountMinor` | `Long?` | `null` | Для рахунку обов’язково `> 0`; для документа `null`. `3550` означає 35,50 одиниць валюти |
| `currency` | `RecordCurrency?` | `null` | Для рахунку EUR, UAH або USD; для документа `null` |
| `isPaid` | `Boolean` | `false` | Оплачений рахунок; для документа завжди `false` |
| `note` | `String?` | `null` | Примітка; порожнє введення форма перетворює на `null` |
| `imagePath` | `String?` | `null` | Резервне поле для шляху зображення. Отримання й показ зображень ще не реалізовані |
| `recognizedText` | `String?` | `null` | Резервне поле для OCR-тексту. Розпізнавання ще не реалізоване |

У моделі немає окремих сутностей користувача, вкладення, рахунку або серверної БД. Зв’язки з такими сутностями не слід додавати до діаграми поточного коду. Схему майбутньої БД потрібно проєктувати окремо на етапі Room/API.

## Допоміжні типи

| Тип / функція | Роль |
| --- | --- |
| `RecordType` | Перелік двох типів запису |
| `RecordCurrency` | Перелік EUR, UAH, USD; усі три валюти мають дві десяткові позиції |
| `RecordStatus` | Обчислювані `ACTIVE`, `DUE_SOON`, `DUE_TODAY`, `EXPIRED`, `OVERDUE`, `PAID` |
| `RecordValidator` | Повертає всі порушення правил моделі як `List<RecordValidationError>` |
| `RecordDates` | Строгий формат `dd.MM.uuuu`, перевірка років 1–9999 та розбір тексту |
| `RecordFormInput` | Текстовий стан полів форми, тип, валюта й оплата; не є сутністю БД |
| `RecordFormResult` | Перевірений `DocumentRecord?` і словник помилок за полями |
| `DeadlineGroup` | `PAST`, `TODAY`, `NEXT_SEVEN_DAYS`, `LATER` |
| `DeadlineSection` | Група та її список записів; похідні дані екрана, окремо не зберігаються |
| `statusOn(today)` | Функція-розширення `DocumentRecord`, не метод, оголошений у тілі data class |
| `groupDeadlineRecords(records, today)` | Виключає оплачені рахунки, групує й сортує терміни |

## Введення та збереження

Форма розбирає дату в `RecordDates.parse`; календарно неможливі дати та рік `0000` відхиляються. `parseAmountMinor` приймає крапку або кому й максимум два десяткові знаки; використовує `BigDecimal`, перевіряє переповнення `Long`, не округлює. Модель додатково перевіряється через `RecordValidator`.

Після успіху `DocTrackApp` додає запис до списку або замінює за ID. Редагування зберігає `imagePath` і `recognizedText`; перетворення рахунку на документ очищує суму, валюту й оплату. Конструктор моделі сам не запускає валідацію: нові сценарії імпорту/API повинні викликати її явно.

`rememberSaveable` і `RecordListSaver` допомагають відновлювати малий навчальний список після відтворення Activity. Це не гарантія постійного зберігання. Перед OCR і збільшенням обсягу даних потрібне перенесення записів у Room.

Повна таблиця статусів і деталі реалізації наведені в [model-rules.md](model-rules.md).
