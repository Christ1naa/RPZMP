# DocTrack

Android-застосунок для обліку документів, рахунків і термінів із запланованою функцією OCR. Курсова робота з дисципліни «Розробка програмного забезпечення мобільних пристроїв».

Пакет `ua.kpi.doctrack`, версія **1.0 (1)**. Kotlin, Jetpack Compose, Material 3, Navigation Compose; minSdk 26, targetSdk 37.

## Поточні можливості

- Вкладки «Записи», «Терміни», «Сервер» з векторними іконками.
- Список, деталі, додавання й редагування документа або рахунку.
- Перевірка полів; дати з роком 1–9999; назва до 120 символів; точні суми у `Long` без округлення.
- Статуси та групування за датами; оплачений рахунок виключається з термінів.
- Спільна поточна дата з оновленням щохвилини у стані STARTED та при ON_RESUME.
- Підтвердження скасування, перенесення елементів форми та одна дія для рядка «Оплачено».
- Відновлення малого навчального стану при відтворенні Activity.

Дані тимчасові: зміни виконуються у списку в пам’яті. `RecordListSaver` не замінює БД; після явного завершення застосунку зміни можуть бути втрачені. Перед OCR і збільшенням обсягу даних записи потрібно перенести в Room. ViewModel, Repository, Room, OCR, нагадування та серверне API ще не реалізовані; вкладка «Сервер» — заглушка.

## Запуск і перевірки

Відкрити **папку `CW`** як Android-проєкт, виконати Gradle Sync, вибрати пристрій з API не нижче 26 та запустити `app`. Локальний шлях Android SDK зберігається в `local.properties` і не повинен потрапляти до Git.

З `CW` у PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
```

Актуальний підсумок для коду після PR №7: **60 предметних JVM-тестів пройшли** в окремому запуску; користувачка також підтвердила успішні Android-збірку, Gradle unit tests і Lint та основні ручні сценарії. Кількість попереджень Lint не встановлена: сам HTML-звіт ще не надано. Умови, дата, коміти й межі підтвердження описані в [протоколі](docs/verification-results.md).
