# DocTrack

Android-застосунок для обліку документів, рахунків і термінів із запланованою функцією OCR. Курсова робота з дисципліни «Розробка програмного забезпечення мобільних пристроїв».

Пакет `ua.kpi.doctrack`, версія **1.0 (1)**. Kotlin, Jetpack Compose, Material 3, Navigation Compose; minSdk 26, targetSdk 37.

## Поточні можливості

- Вкладки «Записи», «Терміни», «Сервер» з векторними іконками.
- Список, деталі, додавання й редагування документа або рахунку.
- Перевірка полів; дати з роком 1–9999; назва до 120 символів; точні суми у `Long` без округлення.
- Статуси та групування за датами; оплачений рахунок виключається з термінів.
- Спільна поточна дата з оновленням щохвилини у стані STARTED та при ON_RESUME.
- Підтвердження скасування, перенесення елементів форми та одна дія для рядка «Оплачено».
- Відновлення малого навчального стану при відтворенні Activity.

Дані тимчасові: зміни виконуються у списку в пам’яті. `RecordListSaver` не замінює БД; після явного завершення застосунку зміни можуть бути втрачені. Перед OCR і збільшенням обсягу даних записи потрібно перенести в Room. ViewModel, Repository, Room, OCR, нагадування та серверне API ще не реалізовані; вкладка «Сервер» — заглушка.

## Запуск і перевірки

Відкрити **папку `CW`** як Android-проєкт, виконати Gradle Sync, вибрати пристрій з API не нижче 26 та запустити `app`. Локальний шлях Android SDK зберігається в `local.properties` і не повинен потрапляти до Git.

З `CW` у PowerShell:

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug --console=plain
```

Підсумок наданих локальних звітів від 03.11.2026: **60 модульних тестів** (2,096 с) і **5 Android UI-тестів** (46,032 с) пройшли; невдалих і пропущених немає. У наданому огляді Lint — **13 попереджень**, помилок не показано. Докази: рисунки П.1–П.3 у [DOCX-звіті](docs/CW_1-4_DocTrack_Report.docx). Звіт описує код [`ed87958a`](https://github.com/Christ1naa/RPZMP/commit/ed87958aa4ebd166453ed66ce38634839d46c396); хеш локальної копії на скриншотах не зафіксований. Під час синхронізації документації 04.11.2026 збірка, тести та Lint повторно не запускалися. Умови й межі підтвердження описані в [протоколі](docs/verification-results.md).

## Перевірки інтерфейсу на пристрої

У `app/src/androidTest` додано п’ять предметних Compose UI-тестів замість початкового тесту назви пакета. Вони перевіряють форму, оплату рахунку, скасування, навігацію та відновлення стану. Для запуску потрібен емулятор або пристрій з API ≥26:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest --console=plain
```

У наданому Android-звіті всі п’ять UI-тестів успішні (рис. П.2 DOCX). Окремий JVM-прогін не перевіряє Compose. `StateRestorationTester` перевіряє Compose saved state; це не повна перевірка реального повороту Activity або завершення процесу. Адаптація списку та порожніх екранів покращена прокручуванням; заголовки й конкретні помилки полів мають семантику для засобів доступності. Фінальну перевірку TalkBack слід виконати вручну.
