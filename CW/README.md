# DocTrack

Курсова робота з розробки програмного забезпечення мобільних пристроїв. Android-застосунок для обліку документів, рахунків і термінів із запланованою функцією OCR.

Пакет: `ua.kpi.doctrack`. Інтерфейс: Kotlin, Jetpack Compose, Material 3.

## Поточний стан

- Навігація між вкладками «Записи», «Терміни» та «Сервер».
- Початкові демонстраційні записи та обчислені статуси на картках.
- Перегляд деталей запису, зокрема дати видачі й примітки.
- Спільна форма додавання та редагування з помилками біля полів.
- Поля рахунку: точна сума в найменших одиницях, валюта EUR/UAH/USD та оплата.
- Збереження змін у списку в пам’яті, повернення до оновлених деталей.
- Підтвердження виходу з незбереженої форми; відновлення введення й демонстраційного списку при відтворенні Activity.
- Модель `DocumentRecord`, перевірка через `RecordValidator` і обчислення статусу через `statusOn(today)`.
- 31 тест правил моделі та статусів і 13 тестів перетворення та перевірки введення форми.

[Правила моделей, таблиця статусів і приклад використання](docs/model-rules.md).

Форма використовує `RecordValidator`. Дати вводяться строго як `дд.мм.рррр`, минулі дати дозволені. Назва після обрізання пробілів — 1–120 символів. Сума приймає крапку або кому, максимум два десяткові знаки, без округлення й переповнення `Long`. При зміні рахунку на документ фінансові поля очищуються під час збереження; ID та метадані OCR/зображення під час редагування зберігаються.

Постійного сховища, OCR, нагадувань і серверного API ще немає. `recordListSaver` підтримує лише невеликий навчальний список через saved instance state; це тимчасове рішення до Room, а не сховище для великих даних. Після повного закриття й нового запуску зміни можуть бути втрачені. [Сценарії ручної перевірки форми](docs/form-checks.md).

## Перевірки

З папки `CW` у PowerShell:

```powershell
.\gradlew.bat :app:testDebugUnitTest --console=plain
```

2 листопада 2026 року всі 31 новий тест пройшли в окремому JVM-запуску JUnit 4.13.2 (Kotlin 1.9.24, JDK 17, target JVM 11) на незмінених Kotlin-файлах моделі та тестів. Повний Gradle-запуск у середовищі перевірки не відбувся: завантаження дистрибутива Gradle 9.6.0 завершилося помилкою мережі. Збірку Android і запуск на емуляторі для цих змін тут не перевірено.


3 листопада 2026 року 44 тести моделі, статусів і введення форми пройшли в окремому JVM-запуску JUnit 4.13.2 (Kotlin 1.9.24, JDK 17, target JVM 11). Це перевірка чистої Kotlin-логіки; нові Compose-екрани, saved state, збірка Android та емулятор у цьому середовищі не перевірені через відсутність Android SDK. Перед merge потрібно виконати локальну збірку та сценарії ручної перевірки.
