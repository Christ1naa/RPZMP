# Лекція 12 — Перетворення типів, розширення, scope-функції та infix

## Основне

### Перетворення значень і приведення типів

- `toInt()`, `toLong()`, `toDouble()` та інші `to...()` створюють значення іншого типу. Набір доступних функцій залежить від вихідного типу.
- `"12".toInt()` розбирає число з рядка. `"taras".toInt()` спричиняє `NumberFormatException`. `toIntOrNull()` натомість повертає `null` — зручно для введення користувача.
- `3.9.toInt()` дає `3`: дробова частина відкидається, а не округлюється. Звуження числових типів може втрачати дані: не всі `to...()` перевіряють діапазон і кидають виняток.
- `is` перевіряє фактичний тип, `!is` заперечує перевірку. Після успішної перевірки компілятор може дозволити доступ до членів точнішого типу — це **smart cast**.
- `is` не створює інший об'єкт і не змінює його клас: компілятор уточнює відомий тип у певній гілці коду.

```kotlin
fun printCompany(person: Person) {
    if (person !is Employee) return
    println(person.company) // Тут уже відомо, що person є Employee.
}
```

- У `person is Employee && person.company.isNotBlank()` smart cast діє в правій частині `&&`: вона виконується лише після успішної перевірки.
- У `when` спочатку перевіряйте точніший підтип: `Manager` перед `Employee`, якщо керівник є працівником.
- Для smart cast потрібне стабільне значення. Змінювана властивість, `open`-властивість або власний getter можуть повертати інший об'єкт при наступному читанні. Для властивостей також можуть мати значення видимість і межі модуля.
- Простий спосіб працювати зі змінюваною властивістю: `val phone = owner.phone`, а потім перевіряти саме локальну `phone`.
- Локальний `var` допускає smart cast, якщо компілятор довів, що між перевіркою й використанням він не змінився; захоплення змінної лямбдою може цьому завадити.

| Запис | Призначення | При невдачі |
| --- | --- | --- |
| `value is Employee` | Перевірити тип | `false` |
| `value as Employee` | Використати об'єкт як Employee | Виняток |
| `value as? Employee` | Безпечно спробувати приведення | `null` |
| `"12".toInt()` | Розібрати числовий текст | NumberFormatException для некоректного тексту |
| `"12".toIntOrNull()` | Безпечно розібрати числовий текст | `null` |

`as` не виконує числове перетворення чи розбір тексту. Якщо `value: Any` містить Int, вираз `value as String` не створить рядок. Для текстового представлення є `toString()`.

### Функції розширення

```kotlin
fun Int.square(): Int = this * this
fun String.wordCount(character: Char): Int = count { it == character }
```

- Тип перед крапкою — **тип отримувача (receiver)**. `this` у тілі позначає значення, для якого викликали функцію: `4.square()` дає `16`.
- Розширення дозволяє записати допоміжну функцію як виклик методу. Воно не змінює визначення класу й не додає нового члена до самого класу.
- Зовнішнє розширення не отримує особливого доступу до `private` чи `protected` членів. Доступ визначають звичайні правила видимості.
- Якщо доступний член класу має сумісну сигнатуру, виклик обирає його, а не розширення.
- Розширення вибираються **статично**, за оголошеним типом отримувача. Якщо `val person: Person = Employee(...)`, виклик `person.role()` обирає розширення `Person.role()`.

### Scope-функції

Вони виконують лямбду в контексті об'єкта. Щоб читати код, визначте дві речі: як названо об'єкт усередині й що повертає весь виклик.

| Функція | Звернення до об'єкта | Повертає | Типова потреба |
| --- | --- | --- | --- |
| `obj.let { ... }` | `it` або названий параметр | Останній вираз лямбди | Обчислити похідне значення |
| `obj.run { ... }` | `this` | Останній вираз лямбди | Виконати дії й отримати результат |
| `with(obj) { ... }` | `this` | Останній вираз лямбди | Згрупувати дії над наявним об'єктом |
| `obj.apply { ... }` | `this` | Початковий об'єкт | Налаштувати властивості |
| `obj.also { ... }` | `it` або названий параметр | Початковий об'єкт | Додати логування чи іншу супутню дію |

```kotlin
val length: Int? = email?.let { it.length }
val profile = Profile("Taras").apply { email = "taras@example.com" }
val sameProfile = profile.also { println(it.name) }
```

- `?.let` пропускає блок при null завдяки **`?.`**. Сам по собі `let` можна викликати і для nullable-значення; тоді `it` теж може бути null.
- В `apply` і `also` повертається той самий об'єкт, а не копія. Змінювати його властивості можна, якщо це дозволяє їхній контракт.
- Звичайний `run { ... }` без отримувача лише виконує блок і повертає останній вираз.
- `T.() -> R` — тип лямбди з отримувачем `this`; `(T) -> R` — звичайна лямбда з аргументом. Це зв'язок із темою функціональних типів із лекцій 4–5.
- `::println` — посилання на функцію; `email?.let(::println)` передає значення в println.
- Не вкладайте багато scope-функцій одна в одну: імена `this` та `it` стає важко відстежувати.

### Інфіксна нотація

```kotlin
class Account(var sum: Int) {
    infix fun put(amount: Int) { sum += amount }
}
// account put 150 — те саме, що account.put(150).
```

- Функція має бути членом класу або розширенням, мати `infix` і рівно один звичайний параметр, без `vararg` та значення за замовчуванням.
- Отримувач стоїть ліворуч, аргумент — праворуч: `account put 150`. Назва функції розміщена **між ними**.
- Звичайний виклик із крапкою залишається доступним. Обидва записи разом означають **два виконання**.
- `"UA" to "Україна"` використовує стандартну infix-функцію `to`, що створює `Pair`.
- Інфіксні виклики мають нижчий пріоритет за арифметику; для складних виразів використовуйте дужки.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Чи перетворить `as String` число на текст? Ні, це приведення типу; для тексту потрібен toString().
2. Що повертає невдалий `as?`? Null.
3. Чому не завжди працює smart cast для var-властивості? Повторне читання може дати інше значення.
4. Чи змінює розширення вихідний клас? Ні; це окрема функція зі зручним синтаксисом виклику.
5. Як обирається перевантаження розширення? За оголошеним типом отримувача.
6. Які scope-функції повертають об'єкт? Apply та also.
7. Чим let відрізняється від run? Доступом через аргумент it або отримувач this; обидві повертають результат лямбди.
8. Чому `email?.let` пропускає null? Через безпечний виклик `?.`.
9. Чи можна infix-функції надати два звичайні аргументи? Ні; отримувач не рахується цим єдиним параметром.

## Що запам'ятати та уточнення до PDF

- `!is` та `as?` пишуться як цілі оператори; у PDF трапляються записи `! is` та `as ?`.
- На с. 9 Employee успадковується від **Person**, а не від самого Employee.
- `wordCount()` у PDF рахує входження символу, попри назву «кількість слів».
- На с. 14 треба друкувати `validationResult`, а не неоголошену `emailOfTaras`. Перевірка `email?.run { "valid" }` визначає лише наявність email і не перевіряє його формат.
- У скорочених сигнатурах apply/also в PDF пропущено оголошення `<T>`; наприклад: `inline fun <T> T.apply(block: T.() -> Unit): T`.
- На с. 15 в описі also помилково написано apply: **also → it**, **apply → this**.
- На с. 16 інфіксна назва розташована між отримувачем і аргументом, а не перед ними.
- На с. 17 для extension-версії Account потрібна властивість `var sum: Int`. Сам параметр `sum: Int` без val/var не надає зовнішньому розширенню доступної властивості.
- Результат 1300 у PDF виникає через два поповнення по 150, а не через особливість infix.
