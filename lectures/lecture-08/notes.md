# Лекція 8 — Абстрактні класи, інтерфейси, вкладені та data-класи

## Основне

- `abstract class` описує спільну основу для підкласів. Безпосередньо створити її екземпляр не можна; конструктор виконується під час створення об'єкта підкласу.
- Абстрактний клас може зберігати стан, мати конструктори та звичайні методи. `abstract fun` і `abstract val/var` задають вимоги без реалізації.
- Конкретний підклас реалізує всі абстрактні члени через `override`; інакше він також має бути абстрактним. Для успадковування від абстрактного класу `open` не потрібне.
- `interface` задає контракт: абстрактні властивості й методи та реалізації за замовчуванням. Власного конструктора і полів для зберігання стану інтерфейс не має.
- Властивість інтерфейсу може обчислювати значення через гетер: `val model: String get() = "Невідома модель"`.
- Клас успадковує щонайбільше один клас, але може реалізувати кілька інтерфейсів: `class Car : Movable, Info`.
- Абстрактну `val` можна реалізувати через `val` або `var`; абстрактну `var` — через `var`.
- Якщо успадковано кілька реалізацій одного методу, потрібен власний `override`. `super<Video>.play()` явно обирає конкретну реалізацію.
- Вкладений (nested) клас не зберігає посилання на екземпляр зовнішнього класу: `BankAccount.Details("Олена")`.
- Внутрішній `inner class` пов'язаний з конкретним зовнішнім об'єктом: `account.Transaction(2400)`. Він має доступ до його приватних членів.
- `this@BankAccount.sum` і `this@Transaction.sum` розрізняють однойменні властивості зовнішнього та внутрішнього об'єктів.
- Класи й інтерфейси можуть містити вкладені класи та інтерфейси. Модифікатор `private` обмежує доступ до вкладеного оголошення.
- `data class Person(val name: String, val age: Int)` призначений для даних. Компілятор генерує `equals`, `hashCode`, `toString`, `copy` та `componentN` за властивостями первинного конструктора.
- У data-класу має бути хоча б один параметр первинного конструктора; кожен такий параметр має бути `val` або `var`. Модифікатори `open`, `abstract`, `sealed`, `inner` заборонені.
- `copy(name = "Катерина")` створює новий об'єкт. Це поверхневе копіювання: вкладені об'єкти не копіюються рекурсивно.
- Декомпозиція `val (name, age) = person` використовує `component1()` і `component2()` у порядку властивостей конструктора.

## Приклади з `tasks.kt`

Це **навчальні приклади за змістом PDF**, а не окремо сформульовані викладачем практичні завдання. Окремого переліку завдань чи контрольних запитань у PDF немає.

1. `Figure` і `Rectangle`: абстрактні властивість та метод, спільна реалізація `display()`.
2. `Movable`, `Info`, `Car`, `Aircraft`: кілька інтерфейсів, властивості конструктора, типовий і перевизначений `stop()`.
3. `MediaPlayer`: розв'язання конфлікту `play()` через `super<Тип>`.
4. `BankAccount.Details` і `BankAccount.Transaction`: різниця nested/inner та доступ через `this@BankAccount`. Платіж 2400 із залишку 3400 дає 1000.
5. `Container`: клас та інтерфейс, вкладені в інтерфейс.
6. `Person`: виведення, `==`, `===`, `hashCode()`, `copy()` та декомпозиція. Властивість `city` у тілі класу не враховується при порівнянні та не переноситься через `copy()` — у новому об'єкті вона отримує початкове значення.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Чим абстрактний клас відрізняється від інтерфейсу? Клас може мати конструктор і стан; інтерфейс задає контракт без власних полів стану.
2. Чи потрібно перевизначати всі методи інтерфейсу? Абстрактні — так; методи з типовою реалізацією — за потреби, крім конфліктів успадкування.
3. Чому `inner` створюють через зовнішній об'єкт? Він зберігає посилання саме на цей екземпляр.
4. Як звернутися до зовнішньої однойменної властивості? Через `this@НазваКласу.властивість`.
5. Чому два `Person` із різними містами рівні? `city` оголошено поза первинним конструктором і не входить у згенерований `equals()`.
6. Чим `==` відрізняється від `===`? Перше порівнює через `equals()`, друге перевіряє тотожність посилань.
7. Чи робить `val` весь об'єкт незмінним? Ні: він забороняє переприсвоєння; вкладені змінювані об'єкти можуть змінюватися.

## Що запам'ятати та виправлення до PDF

- У §4.9 є описка «об'єкт інтерфейсу можна створити безпосередньо». Правильно: **не можна** викликати `Movable()`; створюють екземпляр класу або анонімного об'єкта, що реалізує інтерфейс.
- У §4.10.2 правильний синтаксис — `this@B.n`, `this@A.n`; у PDF крапки втрачено. Віднімання записують `this@BankAccount.sum -= this@Transaction.sum`.
- У вимогах до data-класів «var або var» слід читати як **val або var**.
- Не всі методи data-класу дозволено визначати вручну: `toString`, `equals`, `hashCode` можна, а власні `copy` і `componentN` — ні.
