# Лекція 13 — Колекції та послідовності

## Основне

### Яку структуру обрати

| Тип | Що зберігає | Особливість | Створення |
| --- | --- | --- | --- |
| `List<T>` | Впорядковані елементи | Індекси від 0, дублікати дозволені | `listOf(...)` |
| `Set<T>` | Унікальні елементи | Перевірка належності, без звичайного доступу за індексом | `setOf(...)` |
| `Map<K, V>` | Пари ключ–значення | Унікальні ключі, значення можуть повторюватися | `mapOf(key to value)` |
| `Sequence<T>` | Спосіб отримувати елементи під час обходу | Ліниве виконання ланцюжка операцій | `sequenceOf(...)` |

- `Collection<T>` успадковує `Iterable<T>` і є спільним контрактом List та Set. Map не успадковує Collection.
- Iterable надає iterator для обходу. MutableIterable — інтерфейс із змінюваним ітератором, а не функція.
- `size`, `isEmpty()`, `contains()` і `containsAll()` допомагають перевіряти вміст колекції.
- Для змін є `MutableList`, `MutableSet`, `MutableMap`: `mutableListOf()`, `mutableSetOf()`, `mutableMapOf()`.
- **Read-only не означає гарантовано immutable.** Через List не можна викликати add, але той самий список може змінитися через інше посилання типу MutableList.
- **Val фіксує посилання, а не вміст:** `val items = mutableListOf(1)` дозволяє `items.add(2)`.
- `toList()` створює поверхневий знімок складу списку: подальші додавання в початковий список не змінять знімок. Вкладені змінювані об'єкти не копіюються глибоко.

```kotlin
val editable = mutableListOf(1, 2)
val view: List<Int> = editable
editable.add(3)
println(view) // [1, 2, 3]
```

### List

- `list[index]` і `get(index)` читають елемент. Недопустимий індекс спричиняє виняток; `elementAtOrNull(index)` повертає null.
- `first()` та `last()` на порожньому списку кидають NoSuchElementException. Версії `firstOrNull()` та `lastOrNull()` повертають null.
- `indexOf()` та `lastIndexOf()` повертають -1, якщо значення відсутнє.
- У MutableList: `add(value)`, `add(index, value)`, `addAll(...)`, `list[index] = value`, `remove(value)`, `removeAt(index)`, `clear()`.
- Для списку чисел `remove(5)` видаляє перше значення 5, а `removeAt(5)` — елемент із індексом 5.
- `list + value` повертає новий список. Початковий не змінюється. `list - value` видаляє перше входження значення з результату; варіант із набором виключає всі входження значень цього набору.
- `arrayListOf()` створює ArrayList. У більшості контрактів достатньо типу MutableList без прив'язки до конкретної реалізації.

### Set

- Дублікати визначаються за рівністю елементів; хешовані реалізації також використовують hashCode(). Для data class враховуються властивості первинного конструктора.
- `add()` у MutableSet повертає false, якщо такий елемент уже був; `remove()` повертає, чи було щось видалено.
- `LinkedHashSet` / `linkedSetOf()` зберігає порядок додавання. HashSet / `hashSetOf()` не гарантує порядок обходу. Сам контракт Set також не задає універсального порядку.
- `a intersect b` — спільні елементи; `a union b` — унікальні елементи обох; `a subtract b` — елементи a, яких немає в b.
- `set + element` і `set - element` повертають нові набори; для зміни наявного використовуйте MutableSet.add/remove.

### Map

- `"UA" to "Україна"` створює Pair для передачі в mapOf. `to` — infix-функція з лекції 12.
- `map[key]` повертає значення або null. `getOrDefault(key, default)` надає запасне значення для відсутнього ключа.
- Якщо nullable-значення дозволені, null сам по собі не відрізняє відсутній ключ від ключа зі значенням null; використовуйте `containsKey()`.
- `for ((key, value) in map)` розпаковує запис; також доступні `keys`, `values`, `entries`.
- MutableMap: `map[key] = value`, `put(key, value)`, `remove(key)`, `clear()`.
- Повторний запис того самого ключа замінює значення. У `mapOf("A" to 1, "A" to 2)` для A залишиться 2.
- LinkedHashMap зберігає порядок вставлення, HashMap не гарантує порядок обходу.

### Операції з колекціями

Лямбда — правило обробки: **предикат** повертає Boolean; **перетворення** створює нове значення; **селектор** вибирає ключ або характеристику.

```kotlin
val titles = documents
    .filter { it.type == "bill" }
    .map { it.title }
```

Цей код спочатку відбирає рахунки, а потім формує список їхніх назв. Початкова колекція не змінюється.

| Потреба | Функції | Що пам'ятати |
| --- | --- | --- |
| Перевірка та кількість | `all`, `any`, `contains`, `count` | Для порожньої колекції all(predicate) = true, any(predicate) = false |
| Відбір | `filter`, `filterNot`, `filterNotNull` | Повертають елементи за умовою або без null |
| Пошук | `find`, `findLast`, `firstOrNull`, `lastOrNull` | Повертають null за відсутності результату |
| Доступ за позицією | `elementAt`, `elementAtOrElse`, `elementAtOrNull` | OrElse викликає функцію запасного значення |
| Індекс | `indexOf`, `lastIndexOf`, `indexOfFirst`, `indexOfLast` | -1 означає відсутність |
| Перетворення | `map`, `mapIndexed`, `mapNotNull` | Indexed отримує також індекс; NotNull відкидає null-результати |
| Розгортання | `flatMap` | Перетворює елемент на набір, об'єднує набори в один рівень |
| Унікальність | `distinct`, `distinctBy` | Залишається перший елемент для кожного значення або ключа |
| Групи | `groupBy` | Повертає Map<K, List<T>>; є версія із перетворенням значень |
| Сортування | `sorted`, `sortedDescending`, `sortedBy`, `sortedByDescending` | Створюють впорядкований результат |
| Частини | `take`, `drop`, `takeWhile`, `dropWhile`, `chunked` | While працює з початковим неперервним фрагментом |
| Накопичення | `fold`, `reduce` | Fold має початкове значення; reduce починає з першого елемента |
| Числові підсумки | `sum`, `sumOf`, `average`, `minOrNull`, `maxOrNull`, `minOf`, `maxOf`, `minOfOrNull`, `maxOfOrNull` | Тип результату залежить від елементів або селектора |
| Дії та текст | `forEach`, `joinToString` | ForEach повертає Unit; joinToString формує рядок |
| Нове представлення | `toList`, `toSet`, `toHashSet`, `toMap`, `asSequence` | ToMap застосовується до пар ключ–значення |
| Інші операції | `plus`, `minus`, `intersect`, `subtract`, `union`, `shuffled` | Shuffled створює перемішаний результат |

- `takeWhile { it < 3 }` для `[1, 3, 2, 4]` поверне `[1]`: зупиниться на 3. `filter { it < 3 }` поверне `[1, 2]`.
- `fold(0) { sum, item -> sum + item }` для порожнього списку повертає 0. `reduce` без елементів кидає виняток; для цього випадку існує reduceOrNull.
- `maxOf()` і `minOf()` без елементів кидають виняток; версії OrNull повертають null. Average порожньої числової колекції дає NaN.
- Селектори min/max/sum мають різні перевантаження; результати не обмежені лише Double або лише Int, як може здаватися з переліку PDF.

### Sequence: коли виконується обробка

- Ланцюжок `List.filter().map()` зазвичай виконується поетапно відразу й утворює проміжні списки.
- `Sequence.filter().map()` описує лінивий обхід. Потрібні елементи проходять ланцюжок під час споживання результату.
- **Проміжні** операції повертають Sequence: filter, map, distinct, sorted, take тощо. **Термінальні** запускають обхід: toList, first, count, sum, fold, reduce, groupBy, joinToString, forEach. Цикл for також споживає послідовність.
- `first`, `any` чи `take(n).toList()` можуть завершити обхід раніше. Count чи toList без обмеження можуть ніколи не завершитися на нескінченному джерелі.
- Лінивість не гарантує меншу витрату пам'яті для всіх операцій: sorted має отримати й зберегти всі вхідні елементи перед видачею впорядкованого результату.
- `map` і `filter` не накопичують попередні елементи; `distinct` зберігає вже побачені, `sorted` — дані для сортування. Це відмінність stateless і stateful операцій.
- Sequence не кешує результат автоматично. Повторний обхід повторює обчислення, якщо джерело дозволяє повторний обхід.
- Sequence не є автоматично паралельною чи асинхронною. Для коротких простих операцій накладні витрати можуть переважати користь.

| Створення | Приклад | Поведінка |
| --- | --- | --- |
| `sequenceOf` | `sequenceOf(1, 4, 7)` | Послідовність заданих елементів |
| `asSequence` | `items.asSequence()` | Лінивий обхід наявного джерела |
| `generateSequence` | `generateSequence(5) { if (it < 25) it + 5 else null }` | 5, 10, 15, 20, 25; null завершує генерацію |
| `sequence` | `sequence { yield(1); yieldAll(listOf(4, 7)) }` | Поелементна видача за запитом споживача |

- `yield(value)` віддає один елемент і призупиняє builder до наступного запиту. `yieldAll(source)` віддає елементи іншого джерела.
- `generateSequence { nextValueOrNull() }` без seed — **одноразовий** різновид. Повторний обхід кидає IllegalStateException.
- Версія з seed (`generateSequence(5) { ... }`) може обходитися повторно; якщо генератор залежить від зовнішнього змінюваного стану, результати можуть відрізнятися.
- Нескінченне джерело завжди обмежуйте перед операцією, що потребує всіх елементів. Наприклад, `infinite.take(5).sorted().toList()`, а не `infinite.sorted().take(5).toList()`.

## Приклади з `tasks.kt`

Це **навчальні приклади за змістом PDF**, а не окремо сформульовані викладачем практичні завдання. Окремого переліку завдань чи контрольних запитань у PDF немає.

1. MutableList за посиланням List і поверхневий знімок через toList.
2. Доступ, пошук і зміна списків; різниця remove і removeAt; plus без зміни джерела.
3. Set, дублікати, операції множин, LinkedHashSet і HashSet.
4. Map, невідомий ключ, запасне значення, перебір пар і оновлення ключа.
5. Документи й рахунки: filter/map, пошук, групування, сортування, підсумок 80; додатково fold/reduce, очищення null, flatMap, chunked і takeWhile.
6. Усі чотири способи побудови Sequence; обмежене нескінченне джерело.
7. Видимий порядок виконання filter/map для Sequence проти List. До toList лінивий ланцюжок нічого не друкує; результат `[20]` потребує перевірити лише 1 і 2.
8. Distinct/sorted та одноразовий generateSequence без seed; некоректний повторний обхід залишено в коментарі.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Чи гарантує List незмінність даних? Ні, він надає read-only доступ через це посилання.
2. Чи забороняє val додавати елементи в MutableList? Ні, забороняє переприсвоїти саме посилання.
3. Коли обрати Set? Для унікальних значень і перевірки належності.
4. Що станеться при повторному записі ключа Map? Значення заміниться.
5. Чим map відрізняється від filter? Map перетворює значення, filter відбирає елементи.
6. Чим fold відрізняється від reduce? Fold має заданий початок і працює навіть без елементів.
7. Коли запускається filter у Sequence? Під час споживання послідовності, а не побудови ланцюжка.
8. Чи обробляє take(1) завжди лише один елемент джерела? Ні: попередній filter може відхилити багато елементів.
9. Чому sorted перед take не допоможе нескінченному джерелу? Сортування очікує завершення всього джерела.
10. Чи кешує Sequence попередній результат? Ні; збережіть toList(), якщо потрібен готовий повторно використовуваний результат.

## Що запам'ятати та уточнення до PDF

- Kotlin має власні контракти й функції колекцій у `kotlin.collections`; твердження «не має власної бібліотеки й повністю покладається на Java» надто загальне. На JVM багато реалізацій використовують колекції Java.
- У PDF List/Set/Map названі immutable. Точніше — **read-only інтерфейси**; це не гарантія незмінності сховища чи об'єктів усередині.
- Set не задає універсального порядку, але деякі реалізації його зберігають. Не узагальнюйте поведінку HashSet на LinkedHashSet.
- Plus додає елементи до результату, minus виключає їх за правилами конкретного перевантаження; опис plus у PDF містить випадково залишені слова «за винятком».
- Fold і reduce для Sequence — **термінальні** операції; у переліку PDF вони помилково названі проміжними або «проміжними термінальними».
- TakeWhile/dropWhile працюють до першого порушення умови, а не як filter за всією колекцією. Аргумент n мають take/drop, але не takeWhile/dropWhile.
- GenerateSequence не завжди нескінченний: null завершує його. Перевантаження без seed також має обмеження на повторний обхід.
- Методи в переліках часто є extension-функціями, а не власними членами інтерфейсів; користуватися ними можна через звичайний синтаксис виклику.
- Приклади країн у PDF є умовними навчальними даними, а не актуальною статистикою. Тут використані коди країн і демонстраційні записи.
