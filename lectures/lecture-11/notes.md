# Лекція 11 — Винятки, nullable-типи та делеговані властивості

## Основне

### Винятки

- **Виняток** перериває звичайне виконання поточного коду. Якщо відповідний обробник не знайдено, він поширюється до коду, який викликав функцію.
- `try` містить потенційно помилкові операції, `catch` — обробку відповідного винятку, `finally` — завершальні дії.
- Потрібні `try` та хоча б один `catch` або `finally`. Блоків `catch` може бути кілька.
- Після винятку решта поточного блоку `try` пропускається. Виконується перший відповідний `catch`, потім `finally`, після чого можливе продовження програми.
- Конкретні типи ставлять перед загальними: `ArithmeticException`, `ArrayIndexOutOfBoundsException`, потім за потреби `Exception`.
- `message` містить пояснення (може бути `null`); `stackTrace` у Kotlin/JVM — масив кадрів викликів. `printStackTrace()` друкує повну діагностику, зазвичай у stderr.
- `throw IllegalArgumentException("...")` явно створює помилку аргументу. Не треба перехоплювати її, якщо функція не може розумно відновити роботу.
- `try` може бути виразом: результатом є останній вираз виконаного `try` або `catch`; `finally` не визначає значення результату.

```kotlin
val age: Int? = try {
    checkAge(-125)
} catch (e: IllegalArgumentException) {
    null
}
```

### Null і nullable-типи

- `null` означає відсутність значення, а не нуль чи порожній рядок. `String` не допускає `null`, `String?` допускає.
- Значення типу `String?` не можна використати там, де потрібен `String`, поки не встановлено, що воно не є null, або не надано альтернативу.
- **Smart cast**: після `if (text != null)` компілятор може трактувати стабільне значення як `String`. Для змінюваних властивостей чи власних getter це не завжди можливо.

| Запис | Поведінка для null | Результат у прикладі |
| --- | --- | --- |
| `text?.length` | Не викликає getter, повертає null | `Int?` |
| `text ?: "Без тексту"` | Обчислює та повертає праву частину | `String` |
| `text?.length ?: 0` | Замінює відсутню довжину нулем | `Int` |
| `text!!.length` | Викидає `NullPointerException` | `Int`, лише якщо виконання успішне |

- `?.` — безпечний виклик, `?:` — оператор Елвіса, `!!` — твердження, що значення не null.
- `profile?.name?.uppercase()` повертає null, якщо відсутній профіль або його ім'я. `?: "Без імені"` додає запасний результат.
- `!!` не перевіряє дані безпечно: він переносить відповідальність на програміста. Для звичайного відсутнього значення зручніші `?.`, `?:` або перевірка.

### Делеговані властивості

```kotlin
class Person(val name: String, initialAge: Int) {
    var age: Int by AgeDelegate(initialAge)
}
```

- `val/var property: Type by delegate` передає читання та запис властивості іншому об'єкту.
- Для `val` потрібна `operator fun getValue(...)`; для `var` додатково потрібна `operator fun setValue(...)`.
- `thisRef` — власник властивості, наприклад `Person`, а не тип її значення `Int`. Для делегата, придатного різним власникам, часто використовують `Any?`.
- `property: KProperty<*>` описує властивість; `property.name` дає її назву. Потрібен `import kotlin.reflect.KProperty`.
- `getValue()` повертає значення властивості. `setValue(..., value)` отримує нове значення й визначає, чи зберігати його.
- Делегат може зберігати стан, перевіряти дані й виконувати логування. Власні інтерфейси для цього не обов'язкові.
- Делеговану властивість оголошують у тілі класу, а не як параметр первинного конструктора. Параметр конструктора можна передати делегату.
- `class Phone(m: Messenger) : Messenger by m` з лекції 9 делегує реалізацію інтерфейсу. `var age by AgeDelegate(...)` тут делегує доступ до окремої властивості.

## Приклади з `tasks.kt`

Це **навчальні приклади за змістом PDF**, а не окремо сформульовані викладачем практичні завдання. Окремого переліку завдань чи контрольних запитань у PDF немає.

1. Цілочисельне ділення на нуль: `ArithmeticException`, його тип, повідомлення, перший кадр стека та `finally`. Програма продовжує роботу.
2. Недопустимий індекс масиву: конкретний `catch` перед загальним.
3. `checkAge()` і `checkedAgeOrNull()`: `throw`, `try` як вираз; результати для `5`, `-125`, `110` — `5`, `null`, `110`.
4. `printLength()`, `lengthOrZero()`, `displayName()`: smart cast, безпечний виклик, оператор Елвіса й ланцюжок доступу.
5. `assertedLength()`: для `Kotlin` результат `6`; для null виняток перехоплено лише для навчальної демонстрації.
6. `NameDelegate`: два власники з різними іменами; повідомлення про читання друкується при кожному доступі.
7. `AgeDelegate`: `37 → 38`; спроба записати `-139` відхиляється, залишається `38`; запис `110` дозволено.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Чи виконається код після помилкової операції в тому самому try? Ні, керування переходить до обробника.
2. Чи виконається finally без винятку? Так, за нормального виконання конструкції також.
3. Що повертає try як вираз? Останній вираз виконаного try або catch.
4. Чим відрізняються `String?` і `String`? Перший допускає null.
5. Чим `?.` відрізняється від `!!`? Перший повертає null за відсутності об'єкта, другий кидає виняток.
6. Коли обчислюється права частина `?:`? Лише коли ліва дорівнює null.
7. Які методи потрібні делегату var? `getValue()` і `setValue()` з модифікатором `operator`.
8. Що представляє thisRef? Об'єкт, якому належить властивість.
9. Чи є делегована val автоматично лінивою? Ні: звичайний getValue викликається при кожному читанні; кешування залежить від делегата.

## Що запам'ятати та уточнення до PDF

- Формулювання на с. 9 містять пропущені заперечення: nullable-значення не можна безпосередньо передавати туди, де null **не допускається**. Приклади з локальним значенням, яке точно не null, іноді компілюються завдяки smart cast.
- Еквівалент `name ?: "Undefined"` на с. 10 потребує повного `if/else`; лише `if (name != null)` не присвоює запасне значення.
- `"Taras".uppercase()` дає `TARAS`, а не `TOM`, як у коментарі на с. 11.
- Для делегата використовуйте `KProperty<*>`; запис `KProperty<*?>` на с. 13 некоректний.
- `thisRef` має бути сумісним із типом власника властивості. У PDF опис легко сплутати з типом значення.
- У PDF `checkAge()` дозволяє 110, а setter делегата використовує `< 110`. У наших прикладах початкове значення, checkAge і setter узгоджено: **1..110 включно**. Це навчальна умова, а не універсальне правило віку.
- Додано перевірку початкового віку в `init`: ініціалізація делегата не викликає його setValue автоматично.
- `Exception` не охоплює всю ієрархію `Throwable` (наприклад, JVM `Error`). `finally` виконується при звичайному виході з try, але не гарантується при примусовому завершенні процесу.
- На JVM саме **цілочисельне** ділення на нуль викликає ArithmeticException; ділення Double може дати Infinity або NaN.
