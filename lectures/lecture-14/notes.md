# Лекція 14 — Фільтрація, перевірки, трансформації та групування

## Основне

### Iterable та Sequence: порядок і момент виконання

Ця лекція продовжує тему колекцій із лекції 13. Важливо розуміти не лише назву операції, а й **тип результату та момент виконання лямбди**.

- `List.filter().map()` виконує кожний етап одразу для всіх потрібних елементів і створює проміжні списки.
- `Sequence.filter().map()` створює лінивий ланцюжок. Елементи проходять його під час споживання результату: наприклад, у toList(), firstOrNull() або циклі for.
- У лінивому ланцюжку елемент, який не пройшов filter, не передається наступним операціям.
- `sequence.filter { ... }.take(1).toList()` припиняє обхід після першого відповідного елемента. Для `list.filter { ... }.take(1)` фільтрація вже пройшла весь список.
- Кількість перевірок залежить від даних: take(1) може потребувати багато вхідних елементів, якщо вони не проходять умову.
- Якщо потрібен лише один відповідний елемент, часто достатньо `firstOrNull { ... }` без побудови ланцюжка.
- Sequence не гарантує прискорення: для малих простих наборів накладні витрати можуть переважити користь. Вона не робить код автоматично паралельним.
- Повторний обхід придатної до цього Sequence запускає обчислення знову; результат не кешується. Деякі джерела допускають лише один обхід.
- Stateful-операції, зокрема sorted, можуть вимагати обробити весь набір. Не всі операції здатні передавати результат далі відразу для одного елемента.

У `tasks.kt` той самий пошук першої людини віком понад 30 років робить **3 перевірки для List** і **1 для Sequence** за заданого порядку даних.

### Фільтрація

**Предикат** — функція виду `(T) -> Boolean`. True означає залишити елемент, false — відкинути.

| Функція | Що робить | Приклад |
| --- | --- | --- |
| `filter { ... }` | Залишає відповідні елементи | `people.filter { it.age > 30 }` |
| `filterNot { ... }` | Залишає ті, що не відповідають умові | `names.filterNot { it.length == 5 }` |
| `filterIndexed { index, item -> ... }` | Перевіряє індекс і значення | Парні індекси та довжина 5 |
| `filterIsInstance<Employee>()` | Залишає екземпляри типу та його підтипів | Результат можна читати як Employee |
| `filterNotNull()` | Відкидає null і звужує nullable-тип | List<String?> → List<String> |

- Для List/Set звичайний filter повертає **List**, для Map — **Map**, для Sequence — **Sequence**.
- Для Map предикат отримує запис із ключем і значенням: `map.filter { (key, value) -> ... }`.
- Індекси починаються з нуля. Після попереднього filter індекси у наступному filterIndexed стосуватимуться вже відфільтрованого джерела.
- Filter створює результат, не видаляючи елементи з початкової колекції. Об'єкти всередині результату не копіюються глибоко.
- `filter { it is Employee }` перевіряє тип, але сам по собі не перетворює оголошений тип результату List<Contact> на List<Employee>. Для цього використовуйте filterIsInstance.
- Не використовуйте filterIsInstance для перевірки вкладених generic-аргументів на кшталт List<String>: під час виконання їхні типи загалом стерті.

### Перевірка елементів

| Перевірка | Значення true | Порожній набір |
| --- | --- | --- |
| `all { condition }` | Кожен елемент виконує умову | true |
| `any { condition }` | Хоча б один виконує умову | false |
| `none { condition }` | Жоден не виконує умову | true |
| `any()` | Є хоча б один елемент | false |
| `none()` | Немає елементів | true |

- All повертає true для порожнього набору, бо немає жодного елемента, що порушує умову. Якщо потрібні і непорожність, і відповідність, перевіряйте обидві вимоги.
- All/any/none завершують перевірку, щойно відповідь уже відома. Для Sequence це термінальні операції, але їм не обов'язково обходити всі елементи.
- `contains(value)` або `value in collection` перевіряє належність за рівністю. `containsAll(other)` перевіряє наявність усіх значень іншої колекції, а не кількість їхніх повторів.

### Трансформації

```kotlin
val names: List<String> = people.map { it.name }
val numbered = people.mapIndexed { index, person -> "${index + 1}.${person.name}" }
val parsed = listOf("12", "bad", "7").mapNotNull { it.toIntOrNull() }
```

- `map` перетворює кожен вхідний елемент у вихідне значення. Тип може змінюватися: Person → String, String → Int.
- `mapIndexed` додатково передає індекс; для нумерації від 1 у тексті використовуйте index + 1.
- `mapNotNull` і `mapIndexedNotNull` відкидають **результати перетворення**, що дорівнюють null. Це відрізняється від filterNotNull, який очищує вже наявні null-елементи.
- `flatten()` розгортає **один рівень** вкладених колекцій чи послідовностей. Порядок обходу й дублікати залишаються.
- `flatMap` поєднує перетворення елемента на вкладений набір із його розгортанням; це зв'язок із лекцією 13.
- На Iterable ці перетворення зазвичай повертають List, на Sequence — ліниву Sequence.

### Групування

```kotlin
val fullGroups: Map<String, List<Employee>> = staff.groupBy { it.company }
val namesByCompany: Map<String, List<String>> =
    staff.groupBy({ it.company }) { it.name }
```

- **Селектор ключа** визначає, до якої групи належить елемент.
- Перша версія groupBy зберігає повні об'єкти у списках груп. Друга додатково перетворює елемент перед збереженням, наприклад, залишає лише ім'я.
- Результат — Map, де ключ є назвою/критерієм групи, а значення — List елементів цієї групи.
- У групах зберігається вхідний порядок; ключі результату обходяться в порядку їх першої появи.
- Навіть для Sequence groupBy є **термінальною** операцією: вона споживає джерело та створює Map зі списками. Нескінченне джерело треба спочатку обмежити.
- `for ((company, members) in groups)` перебирає групи, а внутрішній цикл — їхні елементи.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Коли виконується filter у Sequence? Під час споживання результату.
2. Чому filter + take(1) для List може зробити більше перевірок? Filter вже створив повний результат до виклику take.
3. Чи filter змінює початкову колекцію? Ні, повертає окремий результат.
4. Який тип повертає Set.filter? List.
5. Чим filterIsInstance зручніший за filter з перевіркою is? Уточнює тип елементів результату.
6. Що означає all=true для порожнього набору? Немає елемента, який порушив би умову.
7. Чим mapNotNull відрізняється від filterNotNull? Перший перетворює й відкидає null-результати; другий лише прибирає null з джерела.
8. Чи flatten прибирає дублікати? Ні.
9. Що повертає groupBy? Map із ключами груп і списками елементів або перетворених значень.
10. Чи groupBy залишається лінивим для Sequence? Ні, він створює готовий Map.

## Що запам'ятати та уточнення до PDF

- На с. 3–6 умова `name.length == 3` не пропускає жодного з імен Taras, Stepan, Olena. Показаний у PDF результат із Taras цій умові не відповідає. Тут використано **length == 5**, тому проходять Taras та Olena віком понад 30.
- Логи в PDF демонструють правильну ідею порядку обробки, але результати фільтрації потрібно звіряти з фактичними даними.
- Пояснення «весь набір операцій для кожного елемента» стосується відповідних лінивих ланцюжків. Операції на кшталт sorted можуть вимагати весь набір.
- Приклад квадратів на с. 12 фактично використовує List, хоча в тексті названий послідовністю. Для Sequence додайте asSequence() і термінальне отримання результату.
- «Парні позиції» у прикладах означають парні **індекси від 0**, якщо прямо перевіряється index % 2 == 0.
