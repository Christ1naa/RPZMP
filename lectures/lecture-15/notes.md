# Лекція 15 — Сортування, агрегати, об'єднання та вибір елементів

## Основне

### Природний порядок і Comparable

- `sorted()` повертає результат за зростанням природного порядку; `sortedDescending()` — за спаданням. Початковий список не змінюється.
- Для власного класу природний порядок задає `Comparable<T>` і метод `compareTo(other)`.
- Від'ємний результат compareTo означає «перед іншим», 0 — однаковий порядок за цим критерієм, додатний — «після іншого». Не потрібно повертати саме -1 чи 1.
- Нуль за критерієм сортування не обов'язково означає рівність об'єктів через equals.
- Числа впорядковуються чисельно, String — лексикографічно, з урахуванням регістру. Це не локалізоване мовне сортування.

```kotlin
class Person(val name: String, val age: Int) : Comparable<Person> {
    override fun compareTo(other: Person): Int = name.compareTo(other.name)
}
```

Якщо природний порядок визначений за ім'ям, sorted() не почне автоматично сортувати за віком. Для іншого критерію потрібен компаратор або селектор.

### Comparator і сортування за ознакою

| Засіб | Де задається правило | Приклад |
| --- | --- | --- |
| `Comparable<T>` | Усередині класу | `name.compareTo(other.name)` |
| `Comparator<T>` | Окремий об'єкт порівняння | `Comparator<Person> { a, b -> a.age.compareTo(b.age) }` |
| `sortedWith(...)` | Приймає Comparator | `people.sortedWith(compareBy { it.age })` |
| `sortedBy { ... }` | Селектор одного критерію | `people.sortedBy { it.name }` |
| `sortedByDescending { ... }` | Селектор, спадання | `people.sortedByDescending { it.age }` |
| `thenBy { ... }` | Наступний критерій при рівності | `compareBy<Person> { it.age }.thenBy { it.name }` |

- Для чисел безпечніше `a.age.compareTo(b.age)`, ніж `a.age - b.age`: віднімання довільних Int може переповнитися й змінити знак.
- Сортування є стабільним: елементи з однаковим результатом порівняння зберігають вхідний порядок. ThenBy задає додаткове правило замість покладання на цей порядок.
- `reversed()` повертає зворотний порядок, а не сортує за спаданням. Для невідсортованого джерела це різні операції.
- `shuffled()` повертає перемішаний список. Точний порядок випадковий; можна передати Random(seed) для відтворення прикладу в однаковому середовищі.
- Для MutableList `reverse()` та `shuffle()` змінюють наявний список і повертають Unit. Не плутайте з reversed()/shuffled().
- На Sequence sorted/sortedBy повертають Sequence, проте сортування потребує всіх вхідних елементів. Для нескінченного джерела спочатку застосуйте обмеження take(n).

### Агрегатні операції

| Функції | Що повертають | Приклад |
| --- | --- | --- |
| `minOrNull`, `maxOrNull` | Мінімальний/максимальний елемент природного порядку | Мінімальне число |
| `minByOrNull`, `maxByOrNull` | Вихідний об'єкт за значенням селектора | Людину з найменшим віком |
| `minOfOrNull`, `maxOfOrNull` | Саме значення селектора | Найменший вік як Int |
| `minWithOrNull`, `maxWithOrNull` | Вихідний елемент за Comparator | Найкоротший рядок |
| `minOfWithOrNull`, `maxOfWithOrNull` | Значення селектора за Comparator | Найкоротше ім'я людини |
| `average` | Середнє чисел як Double | Для [4, 6, 3, 5, 1, 2] → 3.5 |
| `sum`, `sumOf` | Суму чисел або результатів селектора | `people.sumOf { it.age }` |
| `count`, `count { ... }` | Кількість усіх або відповідних елементів | `people.count { it.age > 30 }` |

- OrNull повертає null на порожньому наборі. Версії minOf/maxOf без OrNull на порожньому наборі кидають NoSuchElementException.
- Average порожнього числового набору повертає NaN; sum порожнього списку Int — 0.
- By повертає **елемент**, Of — **значення ознаки**. Наприклад, `minByOrNull { it.age }` дає Person, а `minOfOrNull { it.age }` — Int.
- Для однакового мінімального/максимального критерію ці OrNull-функції повертають перший відповідний елемент; не потрібно очікувати випадкового вибору.
- Для Sequence агрегатні операції термінальні. Підсумок за всім нескінченним джерелом не завершиться.

### Reduce і fold

```kotlin
val total = listOf(1, 2, 3).reduce { accumulator, item -> accumulator + item }
val text = listOf("Taras", "Olena").fold("People:") { acc, name -> "$acc $name" }
```

- Reduce починає накопичення з **першого елемента**; перший виклик лямбди поєднує перший і другий елементи.
- Для одного елемента reduce повертає його без виклику лямбди. Для порожнього набору кидає виняток; reduceOrNull повертає null.
- Fold отримує початкове значення. Воно передається в перший виклик разом із першим елементом; на порожньому наборі повертається незміненим.
- Тип накопичувача fold може відрізнятися від типу елемента: список Person можна звести до String.
- У наступних кроках accumulator — результат попереднього кроку, item — поточний елемент. Порядок має значення, особливо для віднімання чи побудови тексту.

### Plus, minus, zip та unzip

- `list + element` / `list + other` (plus) повертає новий список; початкові дані залишаються.
- `list - element` (minus) прибирає **перше входження** одиночного значення.
- `list - collection` прибирає **всі входження** значень, що містяться в переданому наборі.
- Для Set результат не містить дублікатів; тип джерела й перевантаження впливають на поведінку.
- Plus для Sequence описує нову послідовність із доданими елементами; це не зміна джерела. Якщо перше джерело нескінченне, доданий після нього хвіст не буде досягнуто.
- `zip` зіставляє елементи **за позиціями**, а не додає всі значення підряд. Результат завершується разом із коротшим джерелом.

```kotlin
val pairs = listOf("red", "blue").zip(listOf("червоний", "синій"))
val labels = listOf("red", "blue").zip(listOf(1, 2)) { word, id -> "$id:$word" }
val (english, ukrainian) = pairs.unzip()
```

- Без transform результат zip містить Pair із first/second; transform створює власний тип результату.
- Unzip розділяє набір пар на два списки. Значення, втрачені під час zip через коротше джерело, відновити не можна.

### Отримання частини набору

| Функція | Результат для `[1, 2, 9, 3, 4]` |
| --- | --- |
| `take(2)` | [1, 2] |
| `takeLast(2)` | [3, 4] |
| `drop(2)` | [9, 3, 4] |
| `dropLast(2)` | [1, 2, 9] |
| `takeWhile { it < 5 }` | [1, 2] |
| `dropWhile { it < 5 }` | [9, 3, 4] |
| `takeLastWhile { it < 5 }` | [3, 4] |
| `dropLastWhile { it < 5 }` | [1, 2, 9] |
| `filter { it < 5 }` | [1, 2, 3, 4] |

- While-версії працюють із неперервним початковим або кінцевим фрагментом. DropWhile перестає **відкидати** після першого невідповідного елемента й залишає весь подальший хвіст.
- Take/drop із n, більшим за розмір, повернуть відповідно весь список/порожній список. Від'ємне n недопустиме.
- `slice(indices)` для List повертає елементи за вказаними індексами, зберігаючи порядок та повтори індексів: `letters.slice(listOf(1, 3, 1))` → `[b, d, b]`.
- Slice не має звичайної версії для Sequence; неправильний індекс спричиняє виняток.
- `chunked(size)` розбиває на послідовні блоки; останній може бути коротшим. Розмір має бути додатним.
- `chunked(2) { it.sum() }` одразу перетворює кожен блок у значення. Тимчасовий блок у transform не слід зберігати для подальшого використання; якщо потрібна копія, створіть toList().
- Take/drop/takeWhile/dropWhile та chunked мають версії для Sequence. Версії з Last із цієї таблиці призначені для списків; не припускайте їх наявність для довільного Iterable чи Sequence.

### Отримання окремих елементів

| Потреба | Звичайний виклик | Якщо елемента немає |
| --- | --- | --- |
| Індекс | `elementAt(index)` | Виняток |
| Індекс із null | `elementAtOrNull(index)` | Null |
| Індекс із запасним значенням | `elementAtOrElse(index) { i -> ... }` | Викликається лямбда з індексом |
| Перший/останній | `first()`, `last()` або версії з предикатом | NoSuchElementException |
| Перший/останній із null | `firstOrNull()`, `lastOrNull()` | Null |
| Випадковий із колекції | `random()` | NoSuchElementException на порожній |
| Випадковий із null | `randomOrNull()` | Null на порожній |

На Sequence пошук елемента за індексом може потребувати послідовного обходу, а пошук last — всього джерела. Random/randomOrNull у цих прикладах застосовуються до колекцій, не до Sequence.

## Питання для самоперевірки

Навчальні питання з короткими відповідями, додані для повторення.

1. Чим Comparable відрізняється від Comparator? Перший задає природний порядок у класі, другий — окреме правило порівняння.
2. Чому compareTo надійніший за віднімання Int? Не ризикує переповненням віднімання.
3. Чим reversed відрізняється від sortedDescending? Перший лише перевертає наявний порядок.
4. MinByOrNull чи minOfOrNull для отримання людини? MinByOrNull; minOfOrNull поверне значення ознаки.
5. Що fold поверне без елементів? Початкове значення.
6. Що буде з повтореннями при `list - "Taras"`? Зникне лише перше входження.
7. Скільки пар створить zip для списків довжин 3 і 2? Дві.
8. Чому dropWhile не дорівнює filterNot? Після першого невідповідного елемента dropWhile перестає відкидати й залишає хвіст.
9. Чи chunked завжди дає однакові за довжиною блоки? Ні, останній може бути коротшим.
10. Як безпечно отримати відсутній елемент? Використати OrNull або elementAtOrElse, залежно від потрібної поведінки.
