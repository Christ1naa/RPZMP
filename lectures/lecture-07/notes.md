# Лекція 7 — Модифікатори видимості, гетери, сетери та перевизначення

## Основне
- Модифікатори видимості визначають, звідки доступні клас, функція, конструктор чи властивість.
- `public` — доступний усюди, де видимий сам тип (за замовчуванням).
- `private` — для члена класу лише всередині класу, для оголошення верхнього рівня — лише в поточному файлі.
- `protected` — всередині класу та його підкласів; для оголошень верхнього рівня не застосовується.
- `internal` — у межах модуля.
- Конструктори також можуть мати модифікатори, наприклад `private constructor(...)`.
- Для властивості `var` можна визначити `get()` і `set(value)`. `val` має тільки гетер.
- `field` у гетері/сетері — спеціальне посилання на backing field цієї властивості.
- Сетер може перевіряти введене значення перед присвоєнням; `get() = "$firstName $lastName"` обчислює значення на основі інших властивостей.
- Щоб перевизначити метод чи властивість, у базовому класі потрібне `open`, у підкласі — `override`.
- Перевизначений метод викликається відповідно до фактичного типу об'єкта.
- `final override` забороняє подальше перевизначення цього члена в нащадках.
- `super.display()` та `super.fullInfo` звертаються до реалізації базового класу.

## Приклади з `tasks.kt`
- `Person` зберігає ім'я у `private` властивості та відкриває `protected` гетер `name`.
- `age` має сетер, який відхиляє значення поза допустимим діапазоном.
- `fullInfo` — обчислювана властивість із гетером.
- `Employee` перевизначає `fullInfo` і `display()`, викликаючи базову реалізацію через `super`.
- `Manager` успадковує `Employee` і перевизначає `display()` ще раз.

Це **самостійно складені приклади для закріплення PDF**, а не завдання, наведені викладачем окремим списком.

## Питання для самоперевірки
1. Чим відрізняються `public`, `private`, `protected` та `internal`?
2. Чому з `main()` не можна викликати `private` або `protected` метод іншого класу?
3. Що робить `set(value)` і чим `field = value` відрізняється від `age = value` у власному сетері?
4. Чому обчислюваний `val fullInfo` може змінювати результат без власного поля?
5. Чому `override` неможливий, якщо базовий метод не `open`?
6. Що виконує `super.display()` у перевизначеному методі?
7. Для чого використовують `final override`?

## Що запам'ятати
- `private` — не те саме, що `protected`: дочірній клас бачить `protected`, але не `private`.
- Не можна оголошувати публічний API з приватним типом параметра.
- Усередині власного сетера використовують `field`, а не повторне присвоєння властивості, щоб уникнути рекурсії.
- `open class` дозволяє успадкування, `open fun` дозволяє перевизначення конкретного методу.
- `final override` зупиняє наступні перевизначення, але не забороняє успадковувати метод.
- PDF лекції 7 присвячений модифікаторам видимості, аксесорам і перевизначенню; інтерфейси й data-класи не є темою цього файлу.
