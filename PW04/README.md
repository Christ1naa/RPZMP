# Практична робота №4 — EnergyForecast

Варіант №1: «Система прогнозування споживання електроенергії». Просунутий рівень, заняття №13–16.

## Початкова основа

Методичку `PW_04 RPZMP.pdf` прочитано повністю: 137 сторінок. Варіант на с. 137 збігається із запитом; приклади сонячних станцій належать варіанту №30.
На с. 45 описано новий проєкт Empty Compose Activity. Тому PW04 є окремим Compose-застосунком, а не копією клієнта та сервера PW03. Використано Gradle Wrapper, каталог версій і значки з попередніх робіт; збережено поділ model/data/logic/ui, MVVM і StateFlow. PW01–PW03 та CW не змінено. Новий application ID: `ua.kpi.energyforecast.pw04`.

## Можливості

- Холодні потоки імітованого лічильника та незалежної прогнозної моделі; `map`, `filter`, `combine`, `retryWhen`, `catch`, гарячий `shareIn`.
- Моніторинг навантаження у кВт і прогнозу споживання у кВт·год/добу, час виміру, стан повторів, кнопки імітації збою та відновлення.
- LazyColumn із картками шести вигаданих будівель-споживачів, вибором та окремим екраном деталей.
- Пошук за назвою; одночасні фільтри типу, статусу та діапазону встановленої потужності; два послідовні критерії сортування з напрямком.
- Google Maps: маркери й InfoWindow, фокус на вибраному об'єкті, виділення та прокручування списку після натискання маркера. Одна відфільтрована колекція для списку й мапи.
- Foreground GPS/мережеве визначення позиції, точний або приблизний дозвіл, повідомлення про вимкнені сервіси, відмову та відкликання дозволу.
- SavedStateHandle для фільтрів і вибраного ID; життєвий цикл зупиняє збір координат і генератори.

## Запуск

1. В Android Studio відкрити **саме `PW04`**, виконати Gradle Sync.
2. Потрібні Android SDK 37, platform-tools, JDK 25 для Gradle, пристрій Android 8.0+ (API 26). Поточна основа: AGP 9.4.1, Wrapper 9.6.0, Compose compiler 2.2.10, BOM 2026.02.01, Maps Compose 6.12.0. Авторитетні версії — у Gradle-файлах.
3. У локальному, виключеному з Git `local.properties` задати `sdk.dir` через Android Studio. Для мапи додати рядок `MAPS_API_KEY=ваш_ключ` або однойменну змінну середовища **перед збіркою**.
4. У власному Google Cloud проєкті увімкнути Maps SDK for Android та налаштувати потрібний доступ Maps Platform. Обмежити ключ Android package `ua.kpi.energyforecast.pw04` і SHA-1 свого підпису (`.\gradlew.bat :app:signingReport`). Ключ до репозиторію не додавати.
5. Запустити застосунок. Для мапи потрібні мережа та Google Play services. Без ключа каталог, деталі й моніторинг доступні, але замість мапи показано інструкцію. Це не симуляція перевіреного Google Maps.
6. Відкрити «Об'єкти й мапа», натиснути «Моя позиція», надати точний або приблизний дозвіл. «GPS» відкриває налаштування геолокації, «Дозволи» — налаштування застосунку для повторного надання доступу після постійної відмови. Позиція відображається лише після нового виміру; фіктивна координата користувача не підставляється.

Підключення Maps Compose й вимоги до ключа звірено з [офіційним README версії 6.12.0](https://github.com/googlemaps/android-maps-compose/tree/v6.12.0). Maps SDK надходить транзитивно; LocationManager використано замість FusedLocationProviderClient, що дозволено домашнім завданням на с. 49.

## Модель

Лічильник повертає Вт; потік перетворює їх на кВт. Для кожного об'єкта:

`E_day = P_measured_kW × hoursPerDay × demandFactor`.

Навантаження змінюється навколо 55% встановленої потужності, коефіцієнт попиту — від 1,00 до 1,10. Об'єкти на обслуговуванні мають нульове навантаження. Коефіцієнт є незалежним імітованим джерелом, а не додатковою потужністю. Опис та його дата статичні; `sampledAt` — час нового виміру. Модель припускає сталий режим протягом заданих годин доби, не враховує погоду та не навчається на історії.

## Межі

Дані повністю вигадані; сервер, Room, авторизація й історія попередніх робіт не потрібні для цієї методички й до PW04 не переносилися. Дані вимірів живуть у пам'яті, після нового процесу симуляція починається знову. SavedStateHandle відновлює стан при системному відновленні Activity, а не після очищення даних/force-stop. Фонових служб та background location немає. Ключ Google Maps користувач налаштовує у власному проєкті; фактичну мапу та GPS потрібно перевірити за переліком у verification.md.
