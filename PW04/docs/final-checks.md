# Підсумкова перевірка й докази PW04 — 16.11.2026

Варіант №1, просунутий рівень. Перевіряли поточний код PW04, а не результати попередніх практичних. Основний пристрій — фізичний Samsung Galaxy A54 / SM-A546B, Android 16, API 36. Для відсутніх Google Play services використано окремий Pixel_6 AVD / API 36. Ручне проходження сценаріїв не заявляється: дії виконували AndroidJUnitRunner, Compose Test API, UiAutomation та Android LocationManager; отримані зображення переглянуто окремо.

## Що саме доведено

- Справжній SDK: тайли, шість демонстраційних маркерів, натискання marker → вибрана/видима картка, «На мапі» → камера, повтор того самого ID після pan, багаторядковий InfoWindow. Комбінований фільтр залишає office-1, reset повертає 6, пошук дає 0.
- Системний діалог телефону: Precise, Approximate, перша відмова, друга/постійна відмова, третій запит без нового діалогу; перехід у власні App info та повернення. Приблизний дозвіл справді надає coarse без fine. Відкликання перевірено перед новою Activity.
- На фізичному телефоні отримано **немокований callback від network provider**: provider=network, isMock=false, у записі наявна accuracy. Тест не встановлює максимально допустимий вік fix і не вимагає accuracy окремою assertion. Приватні координати не записувалися в логи чи кадри. Це не перевірка супутникового GNSS.
- Видимий зелений маркер, точність ±5/6/7 м, другий вимір і off/on провайдерів перевірено через **системні test providers із синтетичними координатами Києва**. Інтерфейс явно позначає «тестова позиція». Це справжні Android LocationManager/Maps, але тестове місцезнаходження. Перший кадр 30 може показувати ще завантаження тайлів; для зеленого маркера використовувати 31/33.
- Вимкнена системна Location, перехід у GPS settings і повернення; реєстрація/очищення підписок, помилки/відкликання, lifecycle; Activity CREATED/RESUMED, recreate і Configuration landscape/portrait. Це не вбивство процесу ОС.
- RETRYING → LIVE для обох незалежних джерел, помилка мінімум > максимум, 6 критеріїв × 2 напрямки; великий **системний** font_scale=1.6 на телефоні й окремий synthetic fontScale=2/малий viewport у тестах.
- Негативні Maps-сценарії розділено: справді порожній ключ, навмисно неправильний ключ, відсутні services на AVD, відсутня мережа. Мережевий сценарій використовує ізольований EnergyMap над Рейк'явіком, zoom=19, без приватного місцезнаходження й без маркерів; це не повний MainActivity/NavHost. Після повтору завантажені справжні тайли.

## Виправлення за результатами перевірок

1. Після off/on провайдера повторна така сама координата відкидалася distance gate. LocationSource тепер повторно реєструє доступні джерела при реальному переході disabled → enabled; початкове enabled-повідомлення не створює цикл. Adapter- і системний UI-тести пройшли.
2. Activity lifecycle-тести чекали картку поза viewport. Очікування й прокрутку виправлено; Search IME закриває клавіатуру й очищує фокус.
3. Початкова перевірка неправильного ключа чекала 20 с реального часу, хоча LaunchedEffect.delay виконувався на віртуальному Compose scheduler. Тест явно просуває mainClock на 20 100 мс; production timeout залишився 20 с. Це узгоджено з [документацією Compose synchronization](https://developer.android.com/develop/ui/compose/testing/synchronization).
4. Частина кадрів знімалася до завершення анімації/рендерингу. Додано очікування idle та кадру, окреме очікування повороту/вмісту App info, очікування SDK після видалення маркерів. Перехідні діагностичні кадри збережено лише у локальному build.

Попередні невдалі спроби й історію Gradle connected task не приховано: [verification.md](verification.md). Зокрема, старий connected task завершився failure попри XML 2/2; фінальні Android-набори запускаються напряму через AndroidJUnitRunner із перевіркою OK, кількості методів і відсутності skip/failure.

## Відтворення

Із кореня репозиторію, після налаштування ignored local.properties, підключення й розблокування власного пристрою:

```powershell
$adbPath = 'C:/Users/tinav/AppData/Local/Android/Sdk/platform-tools/adb.exe'
# DEVICE_SERIAL замінити поточним значенням adb devices; IP/порти в Git не публікуються.
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase baseline
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase keyed
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase absent
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase device
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase invalid
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase state
python PW04/scripts/verify_device.py --adb $adbPath --serial DEVICE_SERIAL --phase restore
python PW04/scripts/collect_maps_evidence.py --adb $adbPath --serial DEVICE_SERIAL
```

baseline не перезаписує існуючий запис: він потрібний для відновлення початкових налаштувань. Host-сценарії вимагають verificationHostSetup=true, мережевий додатково allowNetworkDisruption=true; звичайний масовий запуск їх не виконує. Для цільового запуску SDK скрипт очікує вже зібрані APK з дійсним ключем.

Неправильний ключ збирається лише в окремому APK через змінну середовища, після чого дані лише демонстраційного PW04 очищуються; local.properties не редагується. Системні координати test provider видаляються у finally. Шрифт, Location, дозволи лише PW04 і mock app-op відновлюються; мережевий тест додатково має незалежний device-local watchdog.

Мережевий сценарій виконувати останнім на власному пристрої: `scripts/network_check.py --action launch`, після автоматичного відновлення Wi-Fi знову підключити adb і виконати `--action collect` із новим serial за потреби. Він тимчасово вимикає Wi-Fi/mobile data. Обидва початкові значення звіряються. Services-сценарій: `scripts/verify_services_emulator.py` з --adb і --serial лише виду emulator-...; скрипт додатково перевіряє ro.kernel.qemu, фізичні пристрої відхиляє.
