## Виправлення A04

`ForecastUiState` тепер містить `selectionRevision`. ViewModel зберігає ID для відновлення, а revision збільшує при кожному валідному явному виборі, зокрема повторному для того самого ID. Нові виміри, пошук/сортування та відхилений вибір прихованого ID не створюють події фокусу. ID та revision оновлюються атомарно у внутрішньому SiteSelection; сам ID надалі зберігається у SavedStateHandle, revision є подією поточної ViewModel.

`SiteFocusEffect`, використаний справжнім EnergyMap, залежить від ID, revision, готовності мапи та координат об'єкта. Він:

- не виконує переміщення до готовності мапи;
- після готовності використовує тільки останній видимий вибір;
- повторно фокусує той самий ID за нової revision;
- не фокусує через новий прогноз, порядок колекції або новий екземпляр callback;
- не викликає callback для відфільтрованого/відсутнього ID.

LazyColumn теж враховує revision: повторна подія вибору повертає до картки після ручного прокручування. Службовий рядок стану джерел враховується в індексі. Програмний контракт A04 перевірено; твердження про фактичний pan/recenter Google Maps лишається заблокованим до ключа.

## Маркери й завантаження

`MapPresentation.kt` перетворює тільки visible-колекцію на маркери: незмінні ID/координати, назва, тип, стан, опис, встановлена потужність і прогноз. Ключ композиції — ID; selected маркер блакитний, інші червоні. Фільтр прибирає відповідний маркер, а сортування/нові показники не змінюють його географічну прив'язку. Користувацький маркер лишається окремим зеленим маркером.

Справжній Marker використовує ці поля як title/snippet/contentDescription. Callback обирає ID й повертає false для показу InfoWindow. Поточна реалізація MarkerInfoWindow/SiteInfoWindow замінює стандартний обрізаний snippet; читабельність перевірено на справжніх SDK snapshots. Список і мапа отримують ту саму `state.visible`.

Без ключа мапа не створюється, показано інструкцію. За ключа, але без onMapLoaded протягом 20 с, з'являється повідомлення перевірити ключ/мережу/доступ до SDK та «Повторити мапу». Це повторно створює компонент; це не діагноз конкретної помилки авторизації й не змінює ключ. Готовність скидається для нової мапи, поточний видимий вибір використовується після завантаження. Пізня відповідь запиту «Моя позиція» не повинна перекривати новіший явний вибір об'єкта; GPS-сценарій поки не підтверджений runtime-тестом.

## Перевірки, які не потребують ключа

- `ForecastViewModelTest.repeatedSelectionIsANewActionButReadingsAndSortingAreNot`: повторний ID збільшує revision, оновлення/сортування — ні; прихований ID не породжує подію.
- `MapFocusTest`: той самий ефект, що рухає реальну камеру, викликає тестовий callback координат; перевірено repeated ID, відсутність переміщення на нових даних/порядку/callback, очікування готовності й останній видимий вибір. Це не тест SDK-камери.
- `SiteBrowserTest.repeatedSelectionScrollsBackToTheSameCardAfterManualScroll`: тестова подія маркера повторно повертає список до вже вибраної картки.
- `MapPresentationTest`: IDs, координати й поля InfoWindow збігаються з visible; немає прихованих маркерів/виділення; сортування й нові показники не переміщують об'єкти.
- `MapConfigurationTest`: справжній SiteMapPanel без ключа показує інструкцію й не створює GoogleMap. Цей сценарій пропускається у збірці з ключем.

Фактичні підсумки та пропуски — [verification.md](verification.md). Скріншотів реальної мапи не створено.

## Підготовлені тести справжнього SDK

`GoogleMapSdkTest` викликає той самий EnergyMap, який використовує застосунок. Спостерігач через MapEffect лише дає посилання на SDK для тесту, не підміняє listeners або Marker callbacks. Готовність чекається через справжній onMapLoaded, а не фіктивну затримку.

1. `realCameraRefocusesSameIdAfterPanButNotOnNewReading`: початковий фокус, ручне переміщення SDK-камери, нові дані без скидання viewport, повторний вибір того самого ID повертає target.
2. `realMarkerTouchSelectsItsAssociatedIdAndFocusesCamera`: торкання реального маркера в координаті, отриманій SDK Projection, має вибрати відповідний ID й сфокусувати камеру.

Без ключа ці два тести завершуються на перевірці передумови JUnit assumption до створення мапи. Поточний XML/HTML репортер позначив їх як failure з AssumptionViolatedException (а не skipped), хоча Gradle завершився успішно. Тому звіт не описується як «33 успішні тести»: первинні артефакти збережено, доступний набір запущено окремо з явним виключенням SDK-класу. SDK-тести лишаються заблокованими, не пройденими. Наявність непорожнього ключа теж не гарантує авторизацію: неправильне обмеження/SDK/мережа мають розглядатися як невдала спроба завантаження.

Точна команда доступного набору **без ключа**:

```powershell
.\gradlew.bat :app:connectedDebugAndroidTest --offline --console=plain `
  '-Pandroid.testInstrumentationRunnerArguments.notClass=ua.kpi.energyforecast.pw04.GoogleMapSdkTest'
```

Після налаштування ключа виключення прибрати. Сирі результати першої спроби залишено в ігнорованих `build/verification/stage5-sdk-prerequisites.xml` та `stage5-sdk-prerequisites-summary.html`; фінальний доступний набір має звичайні outputs/reports.

## Історичний перелік завершення A05 (актуальний результат — вище)

Налаштування власного Google Cloud проєкту, SDK, ключа й Android-обмежень описане в [офіційній інструкції Google](https://developers.google.com/maps/documentation/android-sdk/get-api-key). Вона передбачає проєкт із billing та увімкненим Maps SDK for Android; обмеження ключа використовують package і SHA-1. Тут не створювали обліковий запис/проєкт, не вмикали billing і не змінювали хмарні налаштування.

Для поточного debug-підпису цієї машини `:app:signingReport` фактично повернув:

```text
package: ua.kpi.energyforecast.pw04
SHA-1: 18:FB:1F:74:14:D2:37:77:3C:C5:C6:BA:79:04:43:0A:FA:58:5F:4B
```

Це публічний відбиток, не ключ. На іншій машині/для іншого підпису повторити signingReport. Секретне значення зберігати тільки як `MAPS_API_KEY=...` у виключеному `PW04/local.properties` або як змінну середовища перед збіркою; у чат та Git його не додавати. Після зміни значення потрібна перебудова, оскільки metadata й MAPS_CONFIGURED формуються під час Gradle-збірки.

Після налаштування ключа та запущеного AVD:

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:connectedDebugAndroidTest --offline --console=plain
```

Потім перевірити й зібрати реальні докази:

1. Завантажені тайли та всі 6 умовних об'єктів у координатах DemoSites.
2. «На мапі» → камера й блакитний маркер; після pan повторна та сама дія знову фокусує. Новий вимір не повертає камеру самовільно.
3. Реальне торкання іншого маркера → InfoWindow з назвою/типом/описом → виділена й прокручена картка; перевірити повторне торкання після прокрутки списку.
4. Фільтр «Офіс + Активний + 30–50 кВт» → тільки office-1 і його маркер; порожній результат → немає маркерів; скидання → усі 6.
5. Вибір знімається, якщо об'єкт відфільтровано; видалений маркер не залишає InfoWindow. Перевірити late load, повтор завантаження й неправильний ключ/мережу.
6. Зберегти знімки/коротке відео loaded map, обох напрямків взаємодії, повторного фокусу, InfoWindow й фільтрованого результату; записати модель пристрою, API, дату, фактичний результат. Не публікувати сирі логи SDK, якщо вони містять ключ.
