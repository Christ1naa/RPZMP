# Етап 3 — каталог, картки й деталі

Робоча гілка `feature/pw04`, база `032c588`; локальні зміни етапів 1–2 збережено. Обсяг — вимоги №14 (с. 25–26), пов'язаний вміст карток/дат №15 (с. 36–37), переходи та стани деталей. Повна перевірка критеріїв фільтрів/сортування — етап 4; Google Maps/GPS — етапи 5–6.

## Реалізація

| Частина | Поведінка / місце |
|---|---|
| Колекція | `SiteList` отримує `state.visible`; LazyColumn використовує ID як key, а не назву/індекс |
| Картка | Назва, тип, стан, опис, встановлена потужність кВт, виміряне навантаження кВт, добовий прогноз кВт·год, дата опису та час виміру |
| Дії | Card і «Деталі» обирають ID та відкривають окремий екран; «На мапі» лише обирає й лишає каталог відкритим |
| Навігація | `details/{id}`, кодування ID як сегмента, launchSingleTop; об'єкт береться з повного telemetry.readings, незалежно від спискових фільтрів |
| Деталі | `ui/SiteDetails.kt`: окремі lazy-елементи для всіх полів, режиму год/добу, координат і позначки вигаданих даних; «Назад» поза списком |
| WAITING/RETRYING без об'єкта | «Очікуємо дані об'єкта…», стан обох джерел; після даних показується об'єкт потрібного ID |
| FAILED без об'єкта | Повідомлення про недоступні дані та кнопка «Відновити»; не підміняється невідомим ID |
| LIVE без потрібного ID | «Об'єкт не знайдено. Поверніться до каталогу», працює повернення |
| Збережений об'єкт при збої | Дані лишаються доступними й мають статус застарілості, успадкований з етапу 2 |
| Порожній каталог | Окремо від нуля збігів пошуку; некоректний фільтр має свою помилку; стани джерел не називаються порожнім пошуком |
| Розміщення | При ширині ≥600 dp або ширині більшій за висоту список і мапа поруч; у портретному вікні висота мапи — min(230 dp, 32% висоти) |
| Додатковий простір | «Сховати мапу»/«Показати мапу» не змінює вибраний ID; видимість зберігається rememberSaveable |
| Відновлення | SavedStateHandle зберігає запит, критерії та ID; Navigation Compose — маршрут; LazyListState — прокрутку, а подія вибору прокручує до ID з урахуванням службового рядка |

BoxWithConstraints змінює тільки розміщення; список і мапа надалі отримують одну відфільтровану колекцію. Перехід до деталей не передає копію об'єкта, яка могла б застаріти: ID лишається ключем пошуку в поточному повному наборі. Умови й формула прогнозу етапу 2 не змінювалися.

## Автоматичні сценарії

- `SiteBrowserTest`: вміст Card з усіма потрібними полями; callback Card/«Деталі»/«На мапі»; вибір тестового маркера; пошук/скидання; порожній набір проти нуля збігів; збереження видимості мапи/вибору через StateRestorationTester; досяжність останньої картки у viewport 640×300 dp.
- `SiteDetailsTest`: правильний ID у повній колекції, усі поля та прокрутка; WAITING→дані; невідомий ID й «Назад»; FAILED і restart; дані та застарілість при RETRYING.
- `DetailsNavigationTest`: справжній NavHost із невідомим ID → not found → повернення до каталогу.
- `AppSmokeTest`: Card → деталі → назад у MainActivity; запит «Офіс», вибір `office-1`, деталі, `ActivityScenario.recreate()`, збережений маршрут, повернення зі збереженим запитом/вибором. Залишено регресію збоїв обох джерел етапу 2.
- `ForecastViewModelTest`: новий SavedStateHandle із копією значень відновлює запит і ID; наступний вимір змінює дані й час, не змінюючи вибір.

Фактичні результати запуску й невдалі спроби, якщо були, зазначено у [verification.md](verification.md). Тести мапи тут використовують заміну; тести з recreate перевіряють пересоздання Activity, а не повне вбивання процесу ОС. Копіювання SavedStateHandle є unit-перевіркою збережених значень, а не заявою про тест process death.

## Межі та наступні дії

Синтетичний короткий широкий viewport перевіряє доступність списку, не замінює ручне QA на всіх орієнтаціях/масштабах шрифту. Знімки оформлення для звіту потрібно зібрати окремо. Справжню мапу, InfoWindow, GPS, coarse/fine та повторний фокус на тому самому ID (A04) цей етап не перевіряє й не виправляє. Розгорнуту перевірку фільтрів/сортування виконано окремо в [етапі 4](stage-4-query.md).

Зміни обмежено PW04, без commit/push. PW01–PW03, CW та невідстежувану `.codex-attachments/` збережено.
