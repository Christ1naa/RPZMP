## Послідовність демонстрації (5–7 хвилин)

1. Моніторинг: два незалежні джерела, кВт і кВт·год, формула прогнозу; вигадані дані. Збій лічильника, окремо моделі: RETRYING → LIVE, застарілий результат, обмежені повтори.
2. Каталог → Card → деталі → назад. Пояснити ID, дату опису/час виміру та відмінність Card і «На мапі».
3. Офіс + Активний + 30–50 кВт → один office-1, критерії/напрямки та reset. Пошук «Неіснуючий» → 0, діапазон 50–10 → окрема помилка.
4. Справжня Maps: marker → картка, «На мапі» → камера, повтор того самого ID після pan, багаторядковий InfoWindow.
5. «Моя позиція» → системний дозвіл. Для публічних доказів зеленого маркера використано явно позначені test providers Києва. Немокований network callback на фізичному телефоні підтверджено без запису приватних координат; супутниковий GNSS не заявляється.
6. Поворот і повернення Activity, системний великий шрифт. Пояснити SavedStateHandle/rememberSaveable; це не доказ process death.
7. Показати final-checks.md і gallery, розмежувати SDK/повний MainActivity/ізольовані production-компоненти й справжнє/тестове місцезнаходження.

Мережевий negative-тест уже виконано автоматично; повторно вимикати мережу для захисту необов'язково. Його кадри отримано в ізольованому EnergyMap над тестовою ділянкою Рейк'явіка, а неправильний ключ — у MainActivity. Контрольовані WAITING/FAILED/unknown/empty мають явний тестовий підпис.

## Що залишається поза автоматичною перевіркою

Особиста демонстрація й захист, подання та потрібний установі формат файлу. Не виконувалися супутниковий GNSS, TalkBack, foldable/multi-window і вбивство процесу ОС; вони не видаються за пройдені тести. Нові локальні зміни не закомічено й не опубліковано під час збору доказів.
