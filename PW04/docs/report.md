Студентка: Христина Вахрушева, група ТВ-з31 (за README попередніх робіт).
Варіант №1. Рівень — просунутий. Тема: Flow, Coroutines, LazyColumn, пошук і сортування, мапи та GPS.

## Мета й прийняті рішення

Розробити окремий Android-застосунок прогнозування споживання для вигаданих споживачів. Відповідно до с. 45 методички використано основу Empty Compose Activity. Попередні роботи показують перехід від UI до MVVM/Room і REST; у PW04 використано ці архітектурні навички, але джерела локальні, як дозволено на с. 48. Зовнішній сервіс потрібен лише для справжніх картографічних тайлів.

## Архітектура

`DemoSites → DemoTelemetrySource → TelemetryEngine → ForecastViewModel → Compose`.

`SiteQuery → querySites → visible → LazyColumn + GoogleMap`.

`LocationManager → callbackFlow → STARTED lifecycle → маркер користувача`.

Моделі не залежать від UI. У логіці немає Android API. ViewModel має ін'єкцію engine/failureAction для тестів. UI передає дії та відображає StateFlow через collectAsStateWithLifecycle. Деталі мають окремий маршрут `details/{id}` і знаходять об'єкт за стабільним ID у повному наборі, незалежно від фільтра.

## Асинхронна обробка

Холодний потік лічильника генерує кадр щосекунди. Прогнозний коефіцієнт генерується окремо раз на 1,5 с. `filter` перевіряє повноту кадру, невід'ємність і скінченність; `map` перетворює Вт на кВт. `combine` реагує на кожне нове значення будь-якого джерела.

IO-помилки лічильника запускають максимум три повтори із затримками 1, 2, 3 с. Останній кадр зберігається з позначкою RETRYING. Після вичерпання повторів стан FAILED, кнопка «Відновити» через flatMapLatest скасовує попередню сесію та створює нову. CancellationException не перехоплюється як звичайний збій. «Імітувати збій» одноразово спричиняє IOException при наступному кадрі й дозволяє спостерігати відновлення без мережевого сервера.

`shareIn(viewModelScope, WhileSubscribed(5000, 0), replay=1)` створює спільний гарячий потік, який продукує значення незалежно від окремих UI-колекторів протягом активної сесії. Після останньої відписки генератори зупиняються через 5 с; replay очищається. Постійної фонової роботи після закриття застосунку немає.

## Список, фільтри й мапа

Фільтри застосовуються одночасно: назва, тип, статус, включні межі встановленої потужності. Числа підтримують кому й крапку; NaN, нескінченність, від'ємні та перевернуті межі відхиляються з повідомленням. Сортування має перший, другий критерій і стабільний ID. Назви порівнюються українським Collator; потужність, прогноз і дата — відповідними типами.

Картка обирає об'єкт; кнопка «Деталі» відкриває окремий екран. Вибір змінює колір картки й маркера та камеру після завантаження мапи. Натискання маркера відкриває InfoWindow, обирає ID й прокручує LazyColumn. Відфільтрований об'єкт не залишає активного виділення. Карта не перефокусується при кожному новому вимірі.

## Геолокація

Обрано системний LocationManager, прямо дозволений домашнім завданням. Точний дозвіл використовує GPS і доступне мережеве джерело; приблизний — мережеве. Місцезнаходження не вигадується й застаріле lastKnown не видається за поточне. Запити обмежено 5 с/10 м. callbackFlow видаляє слухача через awaitClose; lifecycle STARTED обмежує роботу видимим екраном.

Відсутність дозволу, провайдера, вимкнена геолокація та SecurityException відображаються користувачу. Повернення з налаштувань повторно запускає перевірку дозволів і збір. Кнопка «Моя позиція» запитує доступ і фокусує мапу після свіжого виміру. Зелений маркер користувача відокремлений від червоних/блакитного маркерів споживачів.
